# photo-cull

[简体中文](README.md) · [English](README.en.md) · [日本語](README.ja.md) · **한국어**

photo-cull에는 두 프로그램이 **창 하나**에 함께 들어 있습니다. 오른쪽 위에서 바로 전환하며(⌘1／⌘2) 양쪽의 진행 상태는 그대로 유지됩니다. macOS에서는 터미널이 필요 없는 독립 실행형 **照片工具.app**으로 패키징할 수 있습니다(아래 「Mac 앱」 참고).

- **사진 선별**(macOS는 `启动筛选.command`, Windows는 `启动筛选.bat`을 더블클릭): 내 컴퓨터에서 기술적인 선별을 합니다. 초점, 흐림, 노출, 얼굴과 눈 감음 검출, 연사와 같은 장면 재촬영의 그룹 나누기를 하고, 연사마다 「결정적 순간 가중치」로 한 장을 고릅니다. 고른 사진은 **Claude, ChatGPT, Grok, Gemini, DeepSeek** 또는 OpenAI 호환 비전 모델(Qwen, Kimi, OpenRouter, 로컬 Ollama 등)로 미적 평가를 받을 수 있습니다. 점수는 **10점 만점**이며 로컬 기술 점수는 최고 6점, 6점을 넘는 점수는 AI만 줍니다. 점수는 **별점과 색상 라벨**로 환산해 XMP에 쓰므로 Lightroom Classic과 Capture One에서 모두 읽을 수 있고, 바로 조작할 수 있는 웹 보고서도 만들어집니다.
- **사진 편집**(`启动编辑.command`／`启动编辑.bat`, 기본판): 화면 전체 조정, 곡선, 히스토그램과 파형 모니터. `.cube` LUT와 Lightroom／Photoshop XMP 프리셋을 적용하고 JPEG 또는 16비트 TIFF로 내보냅니다. Leica DNG, Panasonic DNG, 모든 Sony ARW, 후지필름 RAF를 지원합니다.

> 실행 파일 이름은 중국어 그대로입니다: `安装环境`＝환경 설치, `启动筛选`＝사진 선별 실행, `启动编辑`＝사진 편집 실행.

**화면 언어**: 简体中文, English, 日本語, 한국어. 두 프로그램 모두 오른쪽 위에서 바꿀 수 있고 양쪽에 함께 반영됩니다. 보고서, 실행 로그, AI 평가도 고른 언어를 따릅니다. 처음 열 때는 브라우저 언어에 맞춰 자동으로 고릅니다.

**RAW＋JPEG 자동 짝짓기**: 같은 폴더에 있는 같은 이름의 RAW(DNG, ARW, RAF 등)와 JPEG는 사진 한 장으로 취급합니다. 점수는 두 파일에 함께 쓰고, 삭제할 때도 함께 지웁니다.

**안전 보장**
- 이미지 데이터는 절대 바뀌지 않습니다.
  - RAW의 별점은 사이드카 파일 `같은이름.xmp`에 쓰고 원본은 건드리지 않습니다.
  - JPEG의 별점은 파일에 내장된 XMP 세그먼트에 쓰며 메타데이터만 바꿉니다. 쓴 뒤에는 이미지 데이터(카메라가 붙인 다중 사진 미리 보기 포함)가 바뀌지 않았는지 바이트 단위로 확인하고, 조금이라도 이상하면 쓰기를 포기합니다.
- 기존 XMP는 별점과 색상 라벨만 바꾸며 현상 설정, 키워드 등은 그대로 둡니다. 다른 프로그램이 쓴 사이드카 XMP를 처음 바꾸기 전에 `.xmp.cull-bak` 백업을 만듭니다.
- 「삭제」는 파일을 **휴지통**으로 옮길 뿐이라 되살릴 수 있습니다.
- 출력 정리는 기본적으로 **복사**이며 원래 폴더는 그대로 둡니다. 「이동」을 골랐을 때만 원본을 옮깁니다.

## 설치(한 번만)

**macOS**: `安装环境.command`를 더블클릭합니다(또는 실행 파일을 바로 더블클릭해도 처음에 자동으로 설치되며, 두 프로그램이 같은 환경을 씁니다). Python 3.9 이상이 필요합니다([python.org](https://www.python.org/downloads/)).

**Windows(베타)**: `安装环境.bat`를 더블클릭한 뒤 `启动筛选.bat`／`启动编辑.bat`로 엽니다.
- 처음 실행할 때 환경을 자동으로 준비합니다. Python이 없으면 Enter를 눌러 Windows에 들어 있는 winget으로 Python 3.12를 현재 사용자용으로 설치할 수 있고, 이어서 의존성을 내려받습니다(약 3~5분). 그다음부터는 더블클릭하면 바로 열립니다.
- 「Windows의 PC 보호」가 뜨면 「추가 정보 → 실행」을 누르세요.
- 64비트 Windows 10／11(x64)이 필요합니다. ARM용 Windows는 아직 지원하지 않습니다(RAW 디코딩 라이브러리에 ARM 버전이 없음).
- Windows 환경은 `.venv-win`에 따로 두므로 macOS의 `.venv`와 섞이지 않고, 한 폴더를 두 시스템에서 함께 쓸 수 있습니다.

### 새 컴퓨터에 환경 구성

새 컴퓨터이거나 환경이 망가졌을 때는 **`安装环境.command`**(macOS)／**`安装环境.bat`**(Windows)를 더블클릭하세요. 다음을 합니다.

1. Python을 찾습니다(Windows에서 없으면 winget으로 설치할 수 있음).
2. 도구 폴더 안에 독립된 실행 환경(macOS `.venv`, Windows `.venv-win`)을 만들며, 컴퓨터의 다른 Python에는 영향을 주지 않습니다.
3. `requirements.txt`의 의존성을 설치합니다. 먼저 PyPI 공식 저장소를 시도하고 4초 안에 연결되지 않으면 미러로 바꿉니다.
4. 각 구성 요소가 실제로 동작하는지 하나씩 확인하고(numpy, Pillow, OpenCV, rawpy／LibRaw, ExifRead는 필수, HEIC·휴지통·AI 평가는 선택), 내장 LUT와 설정 폴더도 확인한 뒤 결과를 보여 줍니다.

설치한 뒤에는 실행 파일이 빠르게 확인만 하고 바로 열리며, `requirements.txt`가 바뀌면 자동으로 보충 설치합니다.

터미널에서 옵션을 줄 수 있습니다(Windows는 `安装环境.bat 옵션`).

| 옵션 | 동작 |
|---|---|
| `--check` | 확인만 하고 설치하지 않음 |
| `--recreate` | 기존 환경을 지우고 다시 설치(환경이 망가졌거나 Python 버전을 바꿨을 때) |
| `--mirror tuna`／`aliyun`／`ustc`／`pypi`／주소 | pip 저장소 지정(기본 `auto`) |
| `--wheels 폴더` | 로컬 폴더에서 오프라인 설치 |
| `--download 폴더 --target win／mac-arm／mac-intel／linux` | 인터넷이 되는 컴퓨터에서 대상 시스템용 패키지를 미리 내려받고(`--target-python 3.12`와 함께), 옮긴 뒤 `--wheels`로 오프라인 설치 |

macOS에서 직접 설치하려면 「터미널」을 열고:

```bash
cd ~/Desktop/照片筛选工具
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

## Mac 앱(추천)

도구 폴더의 **`打包Mac应用.command`**(Mac 앱 만들기)를 더블클릭하면 `dist/mac/照片工具.app`이 만들어집니다.
- Python과 모든 의존성을 포함하므로 다른 Mac(Apple 실리콘, macOS 11 이상)에서도 바로 쓸 수 있습니다.
- 터미널도 브라우저도 열지 않는 네이티브 창이며, 사진 선별과 사진 편집을 같은 창에서 전환합니다.
- 처음 만들 때는 패키징 도구를 내려받느라 약 3~8분 걸립니다. 별도의 `.venv-build`를 쓰므로 평소의 `.venv`에는 영향이 없습니다.
- 만든 뒤에는 자동으로 자체 점검(의존성, 내장 LUT, 두 서비스)을 하고, 다른 사람에게 보낼 수 있는 `dist/照片工具-<버전>-macOS-app.zip`을 만듭니다.

`照片工具.app`을 「응용 프로그램」으로 끌어다 놓고 Launchpad나 Dock에서 여세요. 창을 닫으면 종료됩니다. 문제가 생겼을 때의 기록은 `~/.photo-cull/logs/app.log`, 패키징 기록은 `dist/mac/build.log`에 있습니다.
다른 사람이 만든 `.app`을 내려받았다면 처음에는 오른쪽 클릭 → 「열기」로 여세요(Apple 공증을 받지 않은 앱입니다).

## 화면 사용법

**`启动筛选.command`** 또는 **`启动编辑.command`**를 더블클릭하면 브라우저에 같은 「사진 도구」 창이 열리고, 각각 선별 또는 편집을 먼저 보여 줍니다. 오른쪽 위의 「사진 선별｜사진 편집」으로 바로 전환하며 다른 실행 파일을 열 필요가 없습니다. 이미 열려 있을 때 다시 더블클릭하면 새로 실행하지 않고 기존 창을 엽니다.

사진 선별:

1. 「선택…」을 눌러 사진 폴더를 고릅니다. 전에 선별한 폴더라면 「이 폴더의 지난 결과 불러오기」로 바로 검토를 이어 갈 수 있습니다.
2. 「로컬만」 또는 「로컬 + AI 정밀 평가」를 고릅니다. 정밀 평가를 고르면:
   - 서비스를 고릅니다: Claude, ChatGPT, Grok, Gemini, DeepSeek 또는 「사용자 지정」.
   - 목록에서 모델을 고르거나(각각 추천／저렴／가장 강력 표시) 「기타」를 골라 직접 입력합니다.
   - 해당 서비스의 API 키를 입력합니다. 「사용자 지정」이면 API 주소도 입력합니다.
3. 처음에는 「연습 모드」를 켜고 판단이 정확한지 먼저 보기를 권합니다.
   필요하면 「출력 정리」를 켜서 평가 후 자동으로 폴더를 나누고 이름을 바꿉니다(아래 「출력 정리」 참고).
4. 「선별 시작」을 누릅니다. AI를 호출하기 전에 장수와 예상 사용량을 보여 주며, 확인해야 호출합니다.
5. 끝나면 보고서가 화면에 나타납니다. 보고서에서는:
   - ★로 1~10점을 매기고(7~10은 AI 구간이지만 직접 매길 수도 있음) ✕로 탈락시킵니다. 바꾼 내용은 바로 별점으로 환산해 RAW와 JPEG에 씁니다.
   - 사진 왼쪽 위의 상자를 체크한 뒤 「선택한 사진 삭제」, 또는 「탈락 사진 모두 삭제」를 누르면 짝지어진 파일과 XMP까지 함께 휴지통으로 옮깁니다.
   - 검토를 마치면 「현재 점수로 정리」를 눌러, 바꾼 점수대로 출력 폴더에 정리합니다.
   - 사진 카드의 「편집」을 누르면 「사진 편집」으로 바로 바뀌어 그 사진을 엽니다.

화면은 이 컴퓨터(127.0.0.1)에서만 돌아가며 밖에서는 접속할 수 없습니다. 터미널 창을 닫으면 종료됩니다.
macOS가 「확인되지 않은 개발자가 배포했기 때문에 열 수 없습니다」라고 하면: 실행 파일을 오른쪽 클릭 → 열기 → 다시 「열기」.

## AI 정밀 평가에 쓸 수 있는 모델

| 서비스 | 모델(첫 번째가 기본값) | API 키 발급처 | 환경 변수 |
|---|---|---|---|
| Claude | `claude-sonnet-5-5`(추천), `claude-haiku-5-5`(저렴), `claude-opus-5-5`(더 강력), `claude-fable-5-1`(가장 강력, 가장 비쌈) | console.anthropic.com | `ANTHROPIC_API_KEY` |
| ChatGPT | `gpt-6.1-sol`(추천), `gpt-6-luna`(저렴), `gpt-6-astra`(가장 강력), `gpt-5.5`(이전 세대) | platform.openai.com | `OPENAI_API_KEY` |
| Grok | `grok-4.7` | console.x.ai | `XAI_API_KEY` |
| Gemini | `gemini-3.8-flash`(추천), `gemini-3.6-flash`, `gemini-3.5-flash-lite`(저렴), `gemini-4-argon`(가장 강력) | aistudio.google.com | `GEMINI_API_KEY`(또는 `GOOGLE_API_KEY`) |
| DeepSeek | `deepseek-flash` | platform.deepseek.com | `DEEPSEEK_API_KEY` |
| 사용자 지정 | 직접 입력 | 각 서비스 | `PHOTO_CULL_CUSTOM_API_KEY` |

- 목록은 2026년 10월에 확인했으며 이미지를 볼 수 있는 모델만 올렸습니다. 새 모델이 나오면 「기타(직접 입력)」를 골라 이름을 입력하세요.
- **DeepSeek**: 지금은 `deepseek-flash`만 이미지 입력을 지원하므로(`deepseek-v4-pro`는 텍스트 전용) 이것 하나만 있습니다.
- **사용자 지정(OpenAI 호환)**: 주소와 모델 이름을 넣으면 Chat Completions로 이미지 입력을 지원하는 어떤 서비스든 쓸 수 있습니다. 예:
  - OpenRouter `https://openrouter.ai/api/v1`
  - Qwen(국제판) `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`(예: `qwen-vl-max`)
  - Kimi `https://api.moonshot.ai/v1`
  - 로컬 Ollama `http://127.0.0.1:11434/v1`, LM Studio `http://127.0.0.1:1234/v1`(키 불필요)

  정확한 주소와 모델 이름은 각 서비스의 문서를 따르세요. DeepSeek와 사용자 지정은 HTTP로 직접 호출하므로 SDK를 따로 설치할 필요가 없습니다.
- API 키는 사용량만큼 과금되며 채팅 구독(Claude Pro, ChatGPT Plus 등)과는 별개입니다.
- 이미 평가한 사진은 다시 과금되지 않습니다: 캐시는 「서비스＋모델＋언어＋이미지」별로 기록합니다. 화면 언어를 바꾸면 평가를 새 언어로 받기 위해 한 번 다시 평가합니다.
- 처음 3번 연속으로 호출이 실패하면(키 오류, 모델 이름 오류, 잔액 부족 등) 자동으로 정밀 평가를 멈춥니다.

## 명령줄

```bash
# 로컬 선별만, 무료
.venv/bin/python cull.py "/Volumes/SSD/2026-10-19 스트리트"

# 먼저 연습: 보고서만 만들고 별점은 쓰지 않음
.venv/bin/python cull.py "사진 폴더" --dry-run

# Claude 평가
export ANTHROPIC_API_KEY="…"
.venv/bin/python cull.py "사진 폴더" --ai

# ChatGPT／Grok／Gemini／DeepSeek
.venv/bin/python cull.py "사진 폴더" --ai --provider openai     # OPENAI_API_KEY
.venv/bin/python cull.py "사진 폴더" --ai --provider grok       # XAI_API_KEY
.venv/bin/python cull.py "사진 폴더" --ai --provider gemini     # GEMINI_API_KEY
.venv/bin/python cull.py "사진 폴더" --ai --provider deepseek   # DEEPSEEK_API_KEY

# 임의의 OpenAI 호환 API(예: OpenRouter)
export PHOTO_CULL_CUSTOM_API_KEY="…"
.venv/bin/python cull.py "사진 폴더" --ai --provider custom --model <모델> --base-url https://openrouter.ai/api/v1

# 보고서, 로그, AI 평가를 한국어로(zh-CN／en／ja／ko)
.venv/bin/python cull.py "사진 폴더" --lang ko

# 별점을 쓴 뒤 탈락 사진(짝지어진 파일 포함)을 휴지통으로
.venv/bin/python cull.py "사진 폴더" --trash-rejects

# 정리: 채택(셀렉트／연사 결정적 순간／사용 가능)／탈락 × JPEG／RAW, 점수로 이름 바꾸기(기본은 복사, --move면 이동)
.venv/bin/python cull.py "사진 폴더" --organize "출력 폴더" --by-result --by-category --by-format --rename

# 셀렉트 기준과 결정적 순간 가중치 바꾸기
.venv/bin/python cull.py "사진 폴더" --ai --pick-ai 7.5 --weights sharp=0.5,eyes=0.3
```

보고서는 `사진 폴더/photo-cull-report/report.html`에 만들어지고, 같은 곳에 Numbers나 Excel로 열 수 있는 `results.csv`도 있습니다. 파일을 직접 연 보고서는 읽기 전용입니다. 점수를 바꾸거나 삭제하려면 프로그램 화면에서 하세요.

## 점수 규칙(10점 만점)

- **로컬 기술 점수**는 최고 **6점**입니다: 초점(같은 묶음 안에서 비교) 60%, 노출 30%, 얼굴과 눈 뜸 10%를 1.0~6.0으로 환산합니다. 「초점이 약간 빗나갔을 수 있는」 사진은 최고 4점이고, 심하게 초점이 나갔거나 노출이 크게 넘치거나 모자란 사진은 탈락입니다.
- **AI 정밀 평가**는 1.0~10.0의 종합 점수를 주며, **6점을 넘는 점수는 AI만 줍니다**. 평가를 받은 사진은 AI 점수를 씁니다.
- 점수는 **내부적으로 0.1 단위**까지 정확하며, 화면·보고서·파일 이름에는 정수 부분만 보여 줍니다.
- XMP에는 **1~5개 별로 환산합니다: 점수 ÷ 2, 내림**(7.9점 → 3★, 8.0점 → 4★). 탈락은 「거부」(Rating −1)로 씁니다.

| 점수 | XMP 별점 | 색상 라벨 |
|---|---|---|
| 10 | 5★ | 초록 |
| 8~9.9 | 4★ | 초록 |
| 6~7.9 | 3★ | 노랑 |
| 4~5.9 | 2★ | 없음 |
| 2~3.9 | 1★ | 빨강 |
| 0~1.9 | 별점 없음 | 없음 |
| 탈락 | 거부(−1) | 빨강 |

**분류**: 채택한 사진은 다음 셋 중 하나가 됩니다(탈락과 읽기 실패는 따로 셉니다).

| 분류 | 정하는 방법 |
|---|---|
| 셀렉트 | 단독 사진이면서 점수가 셀렉트 기준 이상: AI 평가를 받았으면 7점 이상, 로컬 점수만 있으면 5점 이상(둘 다 「고급 설정」이나 `--pick-ai`／`--pick-local`로 바꿀 수 있음) |
| 연사 결정적 순간 | 각 연사(같은 장면 재촬영 포함)에서 결정적 순간 가중치로 고른 한 장 |
| 사용 가능 | 나머지 채택 사진. 연사에서 고르지 않은 컷도 여기에 들어갑니다(최고 4.9점, 즉 2★) |

**결정적 순간 가중치**(기본값. 「고급 설정」이나 `--weights`로 바꿀 수 있음): 같은 연사 안에서 아래 항목의 가중 합계로 한 장을 고릅니다. 각 항목은 연사 안에서 비교하며, 가중치의 합이 1일 필요는 없습니다.

| 항목 | 기본 가중치 | 보는 것 |
|---|---|---|
| 주제 선명도 | 0.35 | 연사 안에서 가장 선명한지 |
| 눈 뜸 | 0.25 | 검출한 얼굴 가운데 눈이 보이는 비율 |
| 미소 | 0.10 | 검출한 얼굴 가운데 웃는 비율 |
| 노출 | 0.15 | 밝기가 알맞고 하이라이트가 날아가거나 암부가 뭉개지지 않았는지 |
| 주제 크기 | 0.15 | 가장 큰 얼굴이 화면에서 차지하는 비율(같은 연사의 다른 컷과 비교) |

연사의 모든 컷에 AI 점수가 있으면(「연사의 나머지 컷도 정밀 평가」를 켰을 때) 「AI 점수 60%＋결정적 순간 점수 40%」로 다시 고릅니다.

**어디에 쓰나**

| 파일 | 별점(점수에서 환산)을 쓰는 곳 |
|---|---|
| RAW(DNG／ARW…) | 같은 이름의 `.xmp` 사이드카. 짝지어진 RAW와 JPEG가 함께 씁니다 |
| JPEG | 파일 내장 XMP(「JPEG 내장 XMP에도 쓰기」를 끄거나 `--no-jpeg-embed`로 끌 수 있음) |
| 단독 HEIC／HIF／PNG | 기본적으로 쓰지 않음. 「단독 JPEG／HEIC에도 XMP 사이드카 쓰기」를 켜면 사이드카를 쓰며 Capture One이 읽습니다 |

**Lightroom Classic**
- 새로 가져오는 사진: 가져올 때 별점을 자동으로 읽습니다.
- 이미 카탈로그에 있는 사진:
  1. 사진을 선택하고 ⌘S(메타데이터를 파일에 저장)를 눌러 카탈로그의 최신 변경을 파일에 먼저 씁니다.
  2. 이 도구를 실행합니다.
  3. 다시 사진을 선택하고 「메타데이터 → 파일에서 메타데이터 읽기」를 실행합니다.
- RAW＋JPEG를 사진 한 장으로 가져왔다면(Lightroom 기본 설정) Lightroom은 RAW의 별점만 보여 줍니다. 두 파일의 별점을 각각 보려면 가져오기 전에 「환경 설정 → 일반」에서 「RAW 파일 옆의 JPEG 파일을 별도의 사진으로 처리」를 켜세요.

**Capture One**
- 「환경 설정 → 이미지 → 메타데이터」에서 XMP 사이드카의 「자동 동기화」를 「전체 동기화」나 「불러오기」로 설정하세요. 그런 다음 폴더를 열거나 이미지에 「XMP에서 메타데이터 다시 불러오기」를 실행하면 별점과 색상 라벨이 보입니다(메뉴 이름은 버전에 따라 다를 수 있음).

**삭제와 카탈로그**
- 이미 Lightroom이나 Capture One에 가져온 사진을 이 도구에서 지우면 그쪽에서는 「파일 없음」으로 표시되니, 그 프로그램에서도 함께 제거하세요.
- 잘못 지웠다면 휴지통을 열어 파일을 원래 폴더로 끌어다 놓으면 됩니다.

## 출력 정리

평가가 끝나면 사진을 출력 폴더로 정리할 수 있습니다(비워 두면 `사진 폴더/정리 결과`). 각 옵션은 따로 켜고 끌 수 있습니다.

- **채택／탈락으로 나누기**: 탈락(X)으로 표시된 사진은 「탈락」, 나머지는 모두 「채택」에 들어갑니다.
- **채택을 다시 셀렉트／연사 결정적 순간／사용 가능으로 나누기**: 연사 결정적 순간은 **연사마다 폴더 하나**(예: `연사012_103045`＝연사 번호＋고른 컷의 촬영 시각)에, 고른 한 장을 넣습니다.
- **다시 JPEG／RAW로 나누기**: HEIC／PNG 등도 JPEG 쪽에 들어갑니다.
- **이름 바꾸기**: 원래 파일 이름 앞에 「점수_기종_」을 붙입니다. 점수는 두 자리라서 이름순으로 정렬하면 점수순이 됩니다. 기종은 EXIF에서 가져옵니다. 예:
  `08_ILCE-1M2_DSC01234.ARW`, `06_LEICA-M11-D_L1003467.DNG`, `X_X-T5_DSCF0001.RAF`.
  탈락은 `X_`이고, 기종 이름의 공백과 특수 문자는 `-`로 바꿉니다.
  **출력 폴더의 파일만 이름을 바꾸며** 원래 파일 이름은 그대로입니다.

폴더 이름은 정리할 때의 화면 언어를 따르고(中文 `保留`／`精选`／`连拍瞬间`／`可用`／`淘汰`, English `Kept`／`Picks`／`Burst moments`／`Usable`／`Rejected`, 日本語도 마찬가지) 정리 기록에 저장되므로, 나중에 보고서에서 동기화할 때도 같은 이름을 씁니다. 분류가 바뀌어 비게 된 폴더(어떤 연사의 결정적 순간 폴더 등)는 자동으로 지웁니다.

모두 켰을 때의 구조:

```
정리 결과/
├── 채택/
│   ├── 셀렉트/
│   │   ├── JPEG/  08_ILCE-1M2_DSC01234.JPG
│   │   └── RAW/   08_ILCE-1M2_DSC01234.ARW  08_ILCE-1M2_DSC01234.xmp
│   ├── 연사 결정적 순간/
│   │   └── 연사012_103045/
│   │       ├── JPEG/  07_ILCE-1M2_DSC01240.JPG
│   │       └── RAW/   07_ILCE-1M2_DSC01240.ARW
│   └── 사용 가능/
│       ├── JPEG/
│       └── RAW/
└── 탈락/
    ├── JPEG/
    └── RAW/
```

**복사 또는 이동**
- **복사**(기본): 원래 폴더는 그대로 두고 출력 폴더에 사본을 만듭니다(두 배의 공간 필요). 나중에 보고서에서 점수를 바꾸면 사본도 알맞은 폴더와 이름으로 옮겨지고, 사진을 지우면 사본도 함께 휴지통으로 갑니다. 다시 정리해도 중복으로 복사하지 않습니다.
- **이동**: 사진을 원래 폴더에서 출력 폴더로 옮깁니다. 이후 보고서에서 점수를 바꾸거나 지우면 옮긴 위치의 파일에 반영됩니다. 이미 Lightroom／Capture One에 가져온 사진은 옮긴 뒤 「파일 없음」으로 표시되니 프로그램에서 폴더 위치를 다시 지정하세요.

**그 밖의 세부 사항**
- 짝지어진 RAW와 JPEG는 함께 처리합니다. RAW의 사이드카 `.xmp`는 RAW를 따라가고 이름도 함께 바뀌므로, 출력 폴더를 Lightroom／Capture One에 가져와도 별점이 보입니다.
- 이름이 겹치면 `-2`, `-3`을 붙이며, 짝지어진 두 파일은 같은 번호를 씁니다.
- 연습 모드에서는 계획만 보여 주고 아무것도 복사하거나 옮기지 않습니다.
- 읽기 실패한 사진과 삭제한 사진은 정리하지 않습니다.
- 출력 폴더를 사진 폴더 안에 두어도 됩니다: 「하위 폴더 포함」을 켜 두면 다음 선별 때 자동으로 건너뜁니다.

## 자주 쓰는 옵션

| 옵션 | 동작 |
|---|---|
| `-r` | 하위 폴더 포함 |
| `--dry-run` | 연습: 별점을 쓰지 않고 보고서만 만듦 |
| `--no-xmp` | 보고서만 |
| `--no-jpeg-embed` | JPEG 파일은 건드리지 않고 RAW 사이드카만 씀 |
| `--ai` | 고른 사진(단독 사진과 각 연사의 결정적 순간)을 AI로 평가해 6점을 넘는 점수를 줌 |
| `--provider claude／openai／grok／gemini／deepseek／custom` | 쓸 서비스 |
| `--model` | 모델 이름 |
| `--base-url` | `--provider custom`일 때의 API 주소 |
| `--lang zh-CN／en／ja／ko` | 보고서, 로그, AI 평가의 언어(기본은 화면 설정이나 시스템 언어) |
| `--ai-alts` | 연사에서 고르지 않은 컷도 평가(비용 증가) |
| `--trash-rejects` | 탈락 사진(짝지어진 파일 포함)을 휴지통으로 |
| `--organize [출력 폴더]` | 평가 후 출력 폴더로 정리. 경로를 안 쓰면 `사진 폴더/정리 결과`, 상대 경로도 사진 폴더 기준 |
| `--by-result`／`--by-category`／`--by-format` | 정리할 때 채택／탈락, 셀렉트／연사 결정적 순간／사용 가능, JPEG／RAW로 폴더를 나눔 |
| `--rename` | 정리할 때 `점수_기종_원래이름`으로 이름 바꾸기 |
| `--move` | 정리할 때 복사 대신 이동 |
| `--yes` | API 호출이나 삭제 전에 묻지 않음 |
| `--burst-gap 15` | 연사: 간격이 이 초 이내이고 화면이 비슷하면 같은 그룹 |
| `--scene-gap 60` | 같은 장면 재촬영: 간격이 이 초 이내이고 화면이 아주 비슷해도 같은 그룹(레인지파인더처럼 느린 촬영용) |
| `--similarity 0.6` | 같은 장면 유사도 기준, 0~1, 클수록 엄격 |
| `--blur-warn 0.58`／`--blur-reject 0.75` | 흐림 정도가 앞의 값을 넘으면 「초점이 약간 빗나갔을 수 있음」 표시, 뒤의 값을 넘으면 탈락 |
| `--pick-ai 7`／`--pick-local 5` | 셀렉트 기준(10점 만점): AI 평가를 받은 사진／로컬 점수만 있는 사진 |
| `--weights sharp=0.35,eyes=0.25,…` | 결정적 순간 가중치(`sharp`, `eyes`, `smile`, `exposure`, `subject`). 쓰지 않은 항목은 기본값 |

## 참고와 한계

- **어떤 파일로 분석하나**: 짝지어진 JPEG가 있으면 JPEG로 분석합니다(원본 크기, 색은 카메라 그대로). JPEG가 없으면 RAW에 내장된 미리 보기를 씁니다. DNG, ARW 같은 TIFF 구조의 RAW와 후지필름 RAF는 프로그램이 내장 미리 보기와 EXIF를 직접 읽으며, CR3 등은 rawpy가 필요합니다.
- **짝짓기 규칙**: 같은 폴더에서 파일 이름이 같고 확장자만 다른 경우(대소문자 구분 없음), 예: `L1003467.DNG`와 `L1003467.JPG`. 다른 폴더에 있으면 짝짓지 않습니다.
- **초점 판정**: 「다시 흐리게 하기」 지표를 씁니다. 화면을 한 번 더 흐리게 했을 때 경계가 얼마나 바뀌는지를 보므로 화면의 디테일 양과 상관이 없고, 가장 선명한 영역만 보므로 배경을 날린 인물 사진도 잘못 판정하지 않습니다. 기본 기준은 Leica M11-D 사진으로 맞췄으며 다른 바디는 조정이 필요할 수 있습니다.
- **얼굴, 눈 감음, 미소 검출**: OpenCV의 전통적인 검출기를 씁니다. 빠르지만 거칠어서 참고 표시와 연사 결정적 순간 고르기에만 쓰며, 이것 때문에 탈락시키지는 않습니다.
- **AI 정밀 평가**:
  - 고른 사진(단독 사진과 각 연사에서 고른 한 장)만 긴 변 1024픽셀 JPEG로 줄여서 보냅니다.
  - 결과는 `ai_cache.json`에 캐시합니다.
  - 모델마다 미적 기준이 다르므로 점수는 참고로만 쓰고 최종 판단은 직접 검토하세요.

## 사진 편집(기본판)

`启动编辑.command`를 더블클릭해 엽니다. 선별 보고서에서 사진 카드 오른쪽 위의 「편집」을 눌러 그 사진을 바로 열 수도 있습니다. 왼쪽 위의 「선별 결과」 버튼은 사진 선별이 가장 최근에 처리한 폴더를 엽니다.

**화면 조정**
- 기본: 색온도, 색조, 노출, 대비, 하이라이트, 섀도, 흰색 계열, 검정 계열, 부분 대비, 생동감, 채도, 흑백. 슬라이더 이름을 더블클릭하면 초기화됩니다.
- 곡선: RGB 전체 곡선과 빨강／초록／파랑 채널 곡선. 클릭해 점 추가, 드래그해 조정, 더블클릭해 삭제.
- **미리 보기**: 화면에서 이미지가 실제로 차지하는 픽셀(Retina 포함)에 맞춰 해상도를 정하고, 창이 커지면 자동으로 다시 렌더링합니다. 미리 보기를 한 번 클릭하면 화면 픽셀 1:1로 확대(스크롤로 세부 확인)되고, 다시 클릭하거나 Esc를 누르면 창에 맞춥니다. 좌우 패널은 제목 표시줄의 ◧ ◨ 버튼이나 키보드 `[` `]`로 접을 수 있고 설정은 기억됩니다. 왼쪽 파일 목록은 「작게／크게」 두 가지 썸네일이 있습니다.
- 모니터: RGB 히스토그램(하이라이트 날아감과 암부 뭉개짐 비율 표시), 휘도 파형／RGB 퍼레이드.
- 「누르고 있으면 비교」로 조정 전의 모습을 볼 수 있습니다.
- **자동 조정**: 도구 막대의 메뉴에서 측광 방식을 고르고 「자동」을 누릅니다. 그다음에도 직접 미세 조정할 수 있습니다. 각 방식은 카메라 회사별 측광 방식과 결과물의 느낌을 바탕으로 한 경험적 설정이며 **카메라 내부 알고리즘을 복제한 것이 아닙니다**. 측광은 편집기의 실제 렌더링 결과를 바탕으로 하므로 RAW의 기본 밝기, JPEG의 밝기, 현재 화이트 밸런스와 고른 렌즈 비네팅이 모두 반영됩니다.

  각 방식은 먼저 **노출**을 정하고, 이어서 **전체 톤**(「대비／검정 계열／흰색 계열」 세 슬라이더)을 정합니다.

  | 방식 | 측광 | 톤 |
  |---|---|---|
  | 평가 측광(전체 화면) | 화면 전체를 6×4 구역으로 나누고 가장 밝은·어두운 15% 구역을 뺀 뒤 평균, 18% 회색 목표 | 중립: 흑점·백점은 적당히, 대비는 그대로 |
  | Leica 클래식 중앙 중점(기본) | M 바디 방식 중앙 중점, 18% 회색보다 약 1/4스톱 낮게. 어두운 장면은 일부만 끌어올림 | 깊음: 검정을 가장 깊게, 기본 대비 +12, 대비를 낮추지 않음 |
  | Leica 다분할 +0.3 EV | Leica 다분할 측광에 +0.3스톱 보정 | Leica와 같지만 조금 더 가볍게(기본 대비 +8) |
  | 후지필름 중앙 중점 | Leica보다 중앙 영역이 넓고 18% 회색 목표. 하이라이트를 더 엄격하게 보호 | 부드러움: 검정을 살짝 띄우고 기본 대비 −5, 완만한 계조 |

  톤 규칙: 밋밋하고 회색빛인 화면은 대비를 조금 더하고, 이미 강한 화면은 덜 더하거나 조금 줄입니다. 대비는 순수한 검정·흰색을 뺀 「내용이 있는」 부분만 보고 판단하므로 넓은 검은 배경의 로우키 사진을 잘못 판정하지 않습니다. 검정은 더 깊게만(순수한 검정이 회색으로 들뜨지 않음), 흰색은 더 밝게만(꽉 찬 흰색이 회색으로 눌리지 않음) 움직이며, 로우키 사진은 억지로 희게, 하이키 사진은 억지로 검게 만들지 않습니다. 모든 방식은 하이라이트가 너무 많이 날아가면 노출을 조금 줄입니다. 지난번 고른 방식은 기억됩니다.

  HDR 동적 측광은 아직 제공하지 않으며 HDR 표시 모드와 함께 나올 예정입니다.
- **렌즈 비네팅**: 「기본」 아래에서 렌즈와 강도를 골라, 바디 보정 전의 클래식 Leica M 렌즈 광학 비네팅(정원형, 완만함, 네 모서리가 가장 어두움)을 흉내 냅니다.

  | 번호 | 렌즈 | 약하게(≈f/5.6) | 중간(≈f/2.8) | 강하게(개방) |
  |---|---|---|---|---|
  | 11874 | Summilux-M 35mm f/1.4 ASPH.(1994, FLE 이전) | −0.6스톱 | −1.2스톱 | −2.2스톱(f/1.4) |
  | 11699 | APO-Summicron-M 35mm f/2 ASPH. | −0.8스톱 | −1.3스톱 | −1.9스톱(f/2) |
  | 11141 | APO-Summicron-M 50mm f/2 ASPH. | −0.5스톱 | −0.9스톱 | −1.4스톱(f/2) |
  | 11672 | Summicron-M 28mm f/2 ASPH.(2016, 2세대) | −1.0스톱 | −1.6스톱 | −2.3스톱(f/2) |

  값은 모서리가 가운데보다 몇 스톱 어두운지입니다. Leica는 비네팅을 그래프로만 공개하고 수치는 밝히지 않으므로, 각 렌즈의 설계 특성(초점 거리, 최대 조리개, 크기)으로 추정한 값입니다. 조리개가 밝고 광각일수록 비네팅이 가운데에 더 가까이서 시작합니다. M 바디는 보통 렌즈 코드로 비네팅을 자동 보정하는데, 여기서는 보정 전의 광학 그대로를 흉내 냅니다. 내보낼 때도 적용되며, 「기본」의 「초기화」로 함께 지워집니다.
- 조정 내용은 `사진 폴더/photo-cull-report/edits/`에 자동으로 저장되며 원본 파일은 바뀌지 않습니다. 「설정 복사／설정 붙여 넣기」로 한 장의 조정을 다른 사진에 쓸 수 있습니다.

**지원 형식**
- RAW는 LibRaw(rawpy)로 디코딩합니다: Leica DNG(M11, Q3, SL 등), Panasonic DNG／RW2, 모든 Sony ARW(비압축, 압축, 무손실 압축), 후지필름 RAF(X-Trans와 베이어, 압축 RAF 포함). DNG의 BaselineExposure는 자동으로 적용합니다.
- JPG, HEIC, TIFF, PNG도 편집할 수 있습니다.
- RAW 디코딩에 실패하면(LibRaw가 아직 모르는 아주 새로운 기종 등) 자동으로 RAW에 내장된 미리 보기로 편집하고 화면에 알립니다. 이때는 화질과 관용도가 제한됩니다.

**스타일(LUT)**
- **내장 LUT**: 도구 폴더의 `luts/`에 LUT 39개가 들어 있습니다. Fujifilm GFX 필름 시뮬레이션 20개(「기종 + 필름 시뮬레이션 이름 (sRGB)」, 예: `GFX50S PROVIA (sRGB)`)와 Leica Look 19개(「Leica Look + 필터 이름 (sRGB)」, 예: `Leica Look CHR (sRGB)`)입니다. **작업 색공간은 모두 sRGB**이므로 sRGB로 변환된 화면에 쓰고, Log나 선형 소스에는 쓰지 마세요. LUT는 공개된 경로에서 모았으며 브랜드 이름은 스타일을 설명하는 데만 씁니다. 기본으로 이것들을 쓰며, 다른 컴퓨터(Windows 포함)로 복사해도 바로 쓸 수 있습니다. 편집 기록에는 이 컴퓨터의 경로가 아니라 「내장 LUT의 이름」을 저장하기 때문입니다.
- **내 LUT 추가**: 「스타일(LUT)」에서 「LUT 추가…」를 눌러 `.cube` 파일을 하나 이상 고르면, 형식을 확인한 뒤 `~/.photo-cull/luts`에 저장하고(도구를 업그레이드해도 남음) 목록의 「내 LUT」 그룹에 보여 줍니다. 항목에 마우스를 올리고 ×를 누르면 제거됩니다.
- 검색한 뒤 LUT를 클릭하면 적용되고 강도를 조절할 수 있습니다. 다른 라이브러리를 쓰려면 「선택…」으로 폴더를 바꾸고, 「내장」을 누르면 돌아옵니다. 외부 라이브러리를 고르면 그 안의 LUT와 프리셋을 모두 보여 줍니다.
- **입력 색공간**: 모두 sRGB로 처리하며 Sony 「ST 표준」／Leica 「STD」의 카메라 화면에 해당합니다.
  - JPEG: ST／STD로 찍은 JPEG는 LUT가 설계된 입력과 정확히 맞습니다.
  - RAW: 편집기의 표준 렌더링을 그 화면의 근사치로 삼아 LUT를 적용합니다.
- S-Log3 등 카메라 Log 변환은 아직 켜져 있지 않습니다(코드에는 남아 있으며 `photo_cull/edit/logspace.py`의 `ENABLE_LOG`).
- 편집기는 XMP 프리셋에 든 Adobe 색 표(RGBTable／LookTable)도 디코딩할 수 있습니다.

**내보내기**
- JPEG(품질 선택, sRGB 색 프로파일과 촬영 정보 포함) 또는 16비트 TIFF. 원본 크기나 긴 변 6000／4000／2048로 줄일 수 있습니다.
- 사진이 있는 폴더의 `photo-cull-export` 하위 폴더로 내보내며 원본을 덮어쓰지 않습니다.
- 내보낼 때는 원본 해상도로 디코딩하고 띠 단위로 렌더링하므로 6,000만 화소 사진도 메모리를 다 차지하지 않습니다. 미리 보기와 내보내기는 같은 처리 파이프라인을 쓰며, 띠마다 다시 여러 스레드로 처리합니다.

**참고**
- 하이라이트와 섀도는 전체 곡선 조정이며, Lightroom처럼 부분 톤 매핑을 하지 않으므로 크게 움직이면 결과가 다릅니다.
- 미리 보기는 백그라운드에서 렌더링합니다: 슬라이더를 끄는 동안은 저해상도, 손을 떼면 고해상도를 보여 줍니다. 렌더링은 컴퓨터의 여러 코어를 모두 씁니다. 큰 JPEG는 미리 보기용으로 줄여서 디코딩하고, 썸네일은 파일에 내장된 작은 미리 보기(Sony JPEG와 ARW에 모두 있음)를 먼저 써서 폴더를 빨리 엽니다.

## 개발자용

프런트엔드와 백엔드를 나눴습니다. Python 패키지 `photo_cull/`은 사진 처리와 API만 맡고, 화면은 `web/`의 HTML／CSS／JS, 문구는 모두 `locales/` 언어 팩에 있습니다. Python을 건드리지 않고 화면을, 코드를 건드리지 않고 문구를 바꿀 수 있습니다.

```
photo_cull/
  imaging/   이미지와 EXIF 읽기(RAW 내장 미리 보기, HEIF, 후지필름 RAF). 선별과 편집이 함께 씀
  cull/      사진 선별: analysis 분석 → grouping 그룹 → scoring 점수 → ai/ 평가 → xmp → organize 정리 → report 보고서. pipeline이 단계를 잇고 cli가 명령줄
  edit/      사진 편집: color 색, lut3d／refs／styles(LUT), presets 프리셋, render 렌더링, auto 자동 조정, session 편집 세션, export 내보내기
  server/    로컬 웹 서버: settings 설정, jobs 작업, apps 두 프로그램 등록, pages 페이지, actions 보고서 동작, handler API, runtime 창 하나
  i18n.py · paths.py · version.py
cull.py · gui.py · desktop.py      진입점(명령줄, 로컬 웹 화면, Mac 앱)
tests/                              테스트: python3 tests/run.py
```
