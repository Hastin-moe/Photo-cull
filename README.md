# 照片工具 photo-cull

**简体中文** · [English](README.en.md) · [日本語](README.ja.md)

工具包含两个程序，放在**同一个窗口**里，右上角一点就切换（⌘1／⌘2），两边的进度和状态都保留。macOS 上可以打包成独立的 **「照片工具.app」**，双击就用，不需要终端（见下文「Mac 应用」）：

- **照片筛选**（双击 `启动筛选.command`）：先在本地做技术筛选，包括对焦、模糊、曝光、人脸与闭眼检测，以及连拍和同场景重拍分组。入围的照片可以再交给 **Claude、ChatGPT、Grok、Gemini、DeepSeek**，或任何 OpenAI 兼容的视觉模型（通义千问、Kimi、豆包、OpenRouter、本地 Ollama 等）做审美细评。最后把**星级和色标**写进 XMP，Lightroom Classic 和 Capture One 都能读到，同时生成一份可以直接操作的网页报告。
- **照片编辑**（双击 `启动编辑.command`，基础版）：对整张画面做调整，包括曲线、直方图和波形图监看；可以套用 `.cube` LUT 和 Lightroom／Photoshop 的 XMP 预设，最后导出 JPEG 或 16 位 TIFF。支持徕卡 DNG、松下 DNG、索尼全部 ARW、富士 RAF。

**界面语言**：简体中文、English、日本語，在两个程序右上角切换（两个程序同步）。报告页、运行日志和 AI 评语都跟随所选语言；第一次打开时按浏览器语言自动选择。

**RAW＋JPEG 自动配对**：同一文件夹里同名的 RAW（DNG、ARW、RAF 等）和 JPEG 会被当成一张照片来评分。打星时两个文件同步标记，删除时两个文件一起删除。

**安全保证**
- 画面数据永远不会被修改。
  - RAW 的星级写在边车文件 `同名.xmp` 里，原文件不动。
  - JPEG 的星级写进文件内嵌的 XMP 段，只改元数据。写完会逐字节核对图像数据（包括相机附带的多图预览）有没有变化，任何异常都会放弃写入。
- 已有的 XMP 只改星级和色标，调色、关键词等内容原样保留。第一次改别的软件写过的边车 XMP 之前，会先备份一份 `.xmp.cull-bak`。
- “删除”只会把文件移到**废纸篓**，可以恢复，不会直接抹掉。
- 整理输出默认是**复制**，原文件夹保持不变；只有你选了「移动」才会搬动原文件。

## 安装（只需一次）

**macOS**：双击 `安装环境.command`（或直接双击启动文件，第一次会自动安装；两个程序共用同一个环境）。需要先装好 Python 3.9 以上（[python.org](https://www.python.org/downloads/)）。

**Windows（测试版）**：双击 `安装环境.bat`，之后用 `启动筛选.bat`／`启动编辑.bat` 打开。
- 第一次运行会自动准备环境：找不到 Python 时，可以按回车用 Windows 自带的 winget 安装 Python 3.12（只装给当前用户）；然后联网安装依赖，约 3–5 分钟。之后每次双击直接打开。
- Windows 弹出「Windows 已保护你的电脑」时，点「更多信息 → 仍要运行」。
- 需要 64 位 Windows 10／11（x64）；ARM 版 Windows 暂不支持（RAW 解码库没有 ARM 版）。
- Windows 的环境放在 `.venv-win`，和 macOS 的 `.venv` 分开，同一个文件夹可以在两种系统间共用。

### 部署新环境（安装环境脚本）

新电脑、或者环境出了问题时，双击 **`安装环境.command`**（macOS）／**`安装环境.bat`**（Windows）。它会：

1. 找到 Python（Windows 上没有的话可以用 winget 自动装）；
2. 在工具文件夹里建独立的运行环境（macOS `.venv`、Windows `.venv-win`），不影响电脑上的其他 Python；
3. 安装 `requirements.txt` 里的依赖。默认先试 PyPI 官方源，4 秒内连不上就自动改用清华镜像；
4. 逐个检查组件能不能真正用（numpy、Pillow、OpenCV、rawpy／LibRaw、ExifRead 必需；HEIC、废纸篓、AI 细评可选），再检查内置 LUT 和设置文件夹，最后列出结果。

装好之后，启动文件只做一次很快的检查就直接打开；`requirements.txt` 有变化时会自动补装。

在终端里可以带参数（Windows 用 `安装环境.bat 参数`）：

| 参数 | 作用 |
|---|---|
| `--check` | 只检查，不安装 |
| `--recreate` | 删掉旧环境重新装（环境坏了、换了 Python 版本时用） |
| `--mirror tuna`／`aliyun`／`ustc`／`pypi`／网址 | 指定 pip 源（默认 `auto`） |
| `--wheels 文件夹` | 从本地文件夹离线安装，不联网 |
| `--download 文件夹 --target win／mac-arm／mac-intel／linux` | 在能联网的电脑上先下载好对方系统的安装包（配合 `--target-python 3.12`），拷过去后用 `--wheels` 离线安装 |

想在 macOS 上手动安装的话，打开「终端」：

```bash
cd ~/Desktop/照片筛选工具
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

从旧版本升级后，启动文件会自动补装新增的依赖。

## Mac 应用（推荐）

双击工具文件夹里的 **`打包Mac应用.command`**，会生成 `dist/mac/照片工具.app`：
- 自带 Python 和全部依赖，拷到别的 Mac（Apple 芯片，macOS 11 以上）也能直接用；
- 原生窗口，不开终端、不开浏览器；照片筛选和照片编辑在同一个窗口里切换；
- 第一次打包要联网下载打包工具，约 3–8 分钟；用单独的 `.venv-build` 环境，不影响平时的 `.venv`；
- 打好后会自动自检（依赖、内置 LUT、两个服务），并生成可以发给别人的 `dist/照片工具-<版本>-macOS-app.zip`。

把 `照片工具.app` 拖进「应用程序」，以后从启动台或程序坞打开。关闭窗口即退出。出问题时的记录在 `~/.photo-cull/logs/app.log`，打包记录在 `dist/mac/build.log`。
从网上下载别人打包的 `.app` 时，第一次请右键 →「打开」（应用没有经过苹果公证）。

## 图形界面

双击 **`启动筛选.command`** 或 **`启动编辑.command`**，浏览器会打开同一个「照片工具」窗口，分别先显示筛选或编辑。右上角的「照片筛选｜照片编辑」直接切换，不需要再去开另一个启动文件；已经开着时再双击，只会打开现有的窗口，不会起第二份。

照片筛选的用法：

1. 点「选择…」，挑一个照片文件夹。如果这个文件夹之前筛选过，可以点「载入这个文件夹上次的结果」，直接继续复核。
2. 选「仅本地筛选」，或者「本地＋AI 细评」。选细评时还要：
   - 选服务商：Claude、ChatGPT、Grok、Gemini、DeepSeek 或「自定义」；
   - 从下拉菜单选模型（每个都标了推荐／便宜／最强），也可以选「其他」手动填写；
   - 填写对应服务商的 API Key；选「自定义」时还要填接口地址。
3. 第一次使用建议勾上「演练模式」，先看看判断准不准。
   需要的话勾上「整理输出」，评分后自动分文件夹、重命名（见下文「整理输出」）。
4. 点「开始筛选」。细评开始前会弹窗显示张数和预计用量，你确认后才会调用。
5. 完成后，报告直接显示在界面里，可以在报告里：
   - 点 ★ 改星级，点 ✕ 标为拒绝，改动立即同步写到 RAW 和 JPEG；
   - 勾选照片左上角的方框，再点「删除所选」；或者点「删除全部淘汰」，配对的文件和 XMP 会一起移到废纸篓。
   - 复核完点「按当前星级整理」，按你改过的星级整理到输出文件夹。
   - 点照片卡片上的「编辑」，会直接切到「照片编辑」并打开这一张。

界面只在本机运行（127.0.0.1），不对外开放。关掉终端窗口即可退出。
如果 macOS 提示“无法打开，因为来自身份不明的开发者”：右键点启动文件 → 打开 → 再点一次「打开」。

## AI 细评可选的模型

| 服务商 | 可选模型（第一个为默认） | API Key 从哪申请 | 环境变量 |
|---|---|---|---|
| Claude | `claude-sonnet-5-5`（推荐）、`claude-haiku-5-5`（便宜）、`claude-opus-5-5`（更强）、`claude-fable-5-1`（最强、最贵） | console.anthropic.com | `ANTHROPIC_API_KEY` |
| ChatGPT | `gpt-6.1-sol`（推荐）、`gpt-6-luna`（便宜）、`gpt-6-astra`（最强）、`gpt-5.5`（上一代） | platform.openai.com | `OPENAI_API_KEY` |
| Grok | `grok-4.7` | console.x.ai | `XAI_API_KEY` |
| Gemini | `gemini-3.8-flash`（推荐）、`gemini-3.6-flash`、`gemini-3.5-flash-lite`（便宜）、`gemini-4-argon`（最强） | aistudio.google.com | `GEMINI_API_KEY`（或 `GOOGLE_API_KEY`） |
| DeepSeek | `deepseek-flash` | platform.deepseek.com | `DEEPSEEK_API_KEY` |
| 自定义 | 自己填写 | 各服务商 | `PHOTO_CULL_CUSTOM_API_KEY` |

- 列表核对于 2026 年 10 月，只列能看图的模型。服务商出了新模型，选「其他（手动填写）」直接填名字即可。
- **DeepSeek**：目前只有 `deepseek-flash` 支持图片输入（`deepseek-v4-pro` 只支持文字），所以只有这一个选项。
- **自定义（OpenAI 兼容）**：填接口地址和模型名，就能接任何支持 Chat Completions 图片输入的服务，例如：
  - 通义千问 `https://dashscope.aliyuncs.com/compatible-mode/v1`（模型如 `qwen-vl-max`）
  - Kimi `https://api.moonshot.cn/v1`
  - 豆包（火山方舟）`https://ark.cn-beijing.volces.com/api/v3`
  - OpenRouter `https://openrouter.ai/api/v1`
  - 本机的 Ollama `http://127.0.0.1:11434/v1`、LM Studio `http://127.0.0.1:1234/v1`（不需要 Key）

  模型名和地址以各家文档为准。DeepSeek 和自定义接口直接走 HTTP，不需要额外安装 SDK。
- API Key 都是按量付费，和网页版订阅（Claude Pro、ChatGPT Plus 等）无关。
- 已经评过的照片不会重复收费：缓存按「服务商＋模型＋语言＋图片」分别记录。换了界面语言会重新细评一次，好让评语换成新语言。
- 如果开头连续 3 张调用失败（Key 错误、模型名不对、余额不足等），程序会自动停止细评，避免白白浪费。

## 命令行

```bash
# 只做本地筛选，不花钱
.venv/bin/python cull.py "/Volumes/SSD/2026-10-19 扫街"

# 先演练：只出报告，不写星级
.venv/bin/python cull.py "照片文件夹" --dry-run

# Claude 细评
export ANTHROPIC_API_KEY="…"
.venv/bin/python cull.py "照片文件夹" --ai

# ChatGPT 细评
export OPENAI_API_KEY="…"
.venv/bin/python cull.py "照片文件夹" --ai --provider openai

# Grok 细评
export XAI_API_KEY="…"
.venv/bin/python cull.py "照片文件夹" --ai --provider grok

# Gemini 细评
export GEMINI_API_KEY="…"
.venv/bin/python cull.py "照片文件夹" --ai --provider gemini

# DeepSeek 细评
export DEEPSEEK_API_KEY="…"
.venv/bin/python cull.py "照片文件夹" --ai --provider deepseek

# 任意 OpenAI 兼容接口（例：通义千问）
export PHOTO_CULL_CUSTOM_API_KEY="…"
.venv/bin/python cull.py "照片文件夹" --ai --provider custom --model qwen-vl-max \
    --base-url https://dashscope.aliyuncs.com/compatible-mode/v1

# 用英文输出报告、日志和 AI 评语（zh-CN／en／ja）
.venv/bin/python cull.py "照片文件夹" --lang en

# 写完星级后，把淘汰的照片（含配对文件）移到废纸篓
.venv/bin/python cull.py "照片文件夹" --trash-rejects

# 评分后整理：保留／淘汰 × JPEG／RAW 两层文件夹，并重命名（默认复制，加 --move 改为移动）
.venv/bin/python cull.py "照片文件夹" --organize "输出文件夹" --by-result --by-format --rename
```

报告生成在 `照片文件夹/photo-cull-report/report.html`。同一目录下还有 `results.csv`，可以用 Numbers 或 Excel 打开。直接双击打开的报告是只读的；要改星级或删除，请在图形界面里操作。

## 结果怎么对应到软件

| 结果 | 星级 | 色标 | 含义 |
|---|---|---|---|
| 精选 | 4–5★ | 绿色 | 只由 AI 细评给出；不开细评时不会出现 |
| 可用 | 3★ | 黄色 | 入围，但不算突出 |
| 连拍备选 | 最多 2★ | 无 | 同一组连拍或重拍里不是最好的那张 |
| 淘汰 | 拒绝（Rating −1） | 红色 | 严重失焦、过曝或欠曝；AI 评 1 星也标红 |

**写到哪里**

| 文件 | 星级写在 |
|---|---|
| RAW（DNG／ARW…） | 同名 `.xmp` 边车文件；配对的 RAW 和 JPEG 共用这一个 |
| JPEG | 文件内嵌 XMP（可关闭：取消勾选「同步写入 JPEG 内嵌 XMP」，或者命令行加 `--no-jpeg-embed`） |
| 单独的 HEIC／HIF／PNG | 默认不写；勾选「单独的 JPEG／HEIC 也写边车 XMP」后写边车，Capture One 会读 |

**Lightroom Classic**
- 新导入的照片：导入时会自动读取星级。
- 已在图库中的照片：
  1. 先选中照片，按 ⌘S（存储元数据到文件），确保目录里的最新修改已经写进文件；
  2. 运行本工具；
  3. 最后选中照片，执行「元数据 → 从文件读取元数据」。
- RAW＋JPEG 如果是作为一张照片导入的（Lightroom 默认设置），Lightroom 只显示 RAW 的星级。想分别看到两个文件的星级，导入前在「偏好设置 → 常规」里勾选「将 RAW 文件旁边的 JPEG 文件视为单独的照片」。

**Capture One**
- 在「偏好设置 → 图像 → 元数据」里，把 XMP 边车的「自动同步」设为「完全同步」或「仅读取」。之后打开文件夹，或对图像执行「从 XMP 重新载入元数据」，就能看到星级和色标（菜单名称以你的 C1 版本为准）。

**删除与目录**
- 照片如果已经导入 Lightroom 或 Capture One，在本工具里删除后，软件里会显示“找不到文件”，需要你在软件里一并移除。
- 刚删错了？打开废纸篓，把文件拖回原来的文件夹即可。

## 整理输出

评分完成后，可以把照片整理到一个输出文件夹（不填路径时是 `照片文件夹/整理输出`）。三个选项都可以单独开关：

- **分成 保留／淘汰**：被标为拒绝（X）的进「淘汰」，其余都进「保留」。文件夹名跟随整理时的界面语言（英文为 `Keep`／`Rejected`，日文为「採用」「不採用」）；之后在报告里改星级同步时，沿用当时的名字。
- **再分 JPEG／RAW**：每个里面再按格式分开；HEIC／PNG 等也放进 JPEG。
- **重命名**：在原文件名前加上「星级_机型_」，机型取自 EXIF，比如
  `4_ILCE-1M2_DSC01234.ARW`、`3_LEICA-M11-D_L1003467.DNG`、`X_X-T5_DSCF0001.RAF`。
  拒绝的是 `X_`，没有星级的是 `0_`；机型里的空格和特殊符号换成 `-`。
  **只改输出文件夹里的文件**，原文件名不变。

两层都开时的结构：

```
整理输出/
├── 保留/
│   ├── JPEG/  4_ILCE-1M2_DSC01234.JPG
│   └── RAW/   4_ILCE-1M2_DSC01234.ARW  4_ILCE-1M2_DSC01234.xmp
└── 淘汰/
    ├── JPEG/
    └── RAW/
```

**复制还是移动**
- **复制**（默认）：原文件夹不动，输出里是副本，需要双倍空间。之后在报告里改星级，输出里的副本会自动换到对应的文件夹和名字；删除照片时，副本也一起移到废纸篓。再次整理不会重复复制。
- **移动**：照片从原文件夹搬到输出文件夹。之后报告里的改星级、删除都会作用在新位置的文件上。已经导入 Lightroom／Capture One 的照片，移动后软件会显示“文件丢失”，需要在软件里重新定位文件夹。

**其他细节**
- 配对的 RAW 和 JPEG 一起处理；RAW 的边车 `.xmp` 跟着 RAW 走，重命名时一起改名，所以 Lightroom／Capture One 导入输出文件夹也能看到星级。
- 重名时自动加 `-2`、`-3` 后缀，配对的两个文件用同一个后缀。
- 演练模式下只列出计划，不会复制或移动任何文件。
- 读取失败和已删除的照片不参与整理。
- 输出文件夹放在照片文件夹里面也可以：勾了「包含子文件夹」时，下次筛选会自动跳过它。

## 常用参数

| 参数 | 作用 |
|---|---|
| `-r` | 包含子文件夹 |
| `--dry-run` | 演练：不写星级，只生成报告 |
| `--no-xmp` | 只要报告 |
| `--no-jpeg-embed` | 不改 JPEG 文件，只写 RAW 的边车 XMP |
| `--ai` | 对入围照片做 AI 细评 |
| `--provider claude／openai／grok／gemini／deepseek／custom` | 用哪家模型 |
| `--model` | 指定模型名 |
| `--base-url` | `--provider custom` 时的接口地址 |
| `--lang zh-CN／en／ja` | 报告、日志、AI 评语的语言（默认跟随界面设置或系统语言） |
| `--ai-alts` | 连拍备选也送去细评（更贵） |
| `--trash-rejects` | 把淘汰的照片（含配对文件）移到废纸篓 |
| `--organize [输出文件夹]` | 评分后整理到输出文件夹；不写路径时为 `照片文件夹/整理输出`，相对路径也以照片文件夹为起点 |
| `--by-result`／`--by-format` | 整理时分 保留／淘汰、JPEG／RAW 文件夹 |
| `--rename` | 整理时重命名为 `星级_机型_原文件名` |
| `--move` | 整理时移动而不是复制 |
| `--yes` | 调用 API 或删除前不再询问 |
| `--burst-gap 15` | 连拍：间隔不超过几秒、画面相近，算同一组 |
| `--scene-gap 60` | 同场景重拍：间隔不超过几秒、画面很像，也算同一组（适合旁轴等慢节奏拍摄） |
| `--similarity 0.6` | 同场景相似度阈值，0–1，越大越严格 |
| `--blur-warn 0.58`／`--blur-reject 0.75` | 模糊度超过前者提示“可能失焦／抖动”，超过后者直接淘汰 |

## 说明与局限

- **分析用哪个文件**：有配对的 JPEG 时，用 JPEG 分析（全尺寸，颜色就是机内效果）；没有 JPEG 时，用 RAW 里嵌入的预览。DNG、ARW 这类 TIFF 结构的 RAW，以及富士 RAF，由程序直接读取内嵌预览和 EXIF；CR3 等格式才需要 rawpy。
- **配对规则**：同一个文件夹里，文件名相同、只有扩展名不同（不分大小写），比如 `L1003467.DNG` 和 `L1003467.JPG`。放在不同文件夹里的不会配对。
- **失焦判定**：用的是“再模糊”指标：把画面再模糊一次，看边缘变化有多大，所以和画面细节多少无关；只取最锐利的区域，背景虚化的人像不会被误判。默认阈值是用 Leica M11-D 的照片校准的，其他机身可能需要微调。
- **人脸和闭眼检测**：用的是 OpenCV 的传统检测器，速度快但比较粗糙，只作提示，不会因此淘汰照片。
- **AI 细评**：
  - 只把入围照片缩成 1024 像素的 JPEG 后上传。
  - 结果缓存在 `ai_cache.json`。
  - 不同模型的审美标准会有差异，评分只是参考，最终取舍请自己复核。

## 照片编辑（基础版）

双击 `启动编辑.command` 打开。也可以在筛选报告里点照片卡片右上角的「编辑」，直接打开那一张。左上角「筛选结果」按钮会打开照片筛选最近处理的文件夹。

**画面调整**
- 基本：色温、色调、曝光、对比度、高光、阴影、白色、黑色、清晰度、自然饱和度、饱和度、黑白。双击滑块名称可以复位。
- 曲线：RGB 总曲线和红／绿／蓝分通道曲线。点击加点、拖动调整、双击删除。
- **预览**：按图片在屏幕上实际占的像素（含 Retina 高分屏）取清晰度，窗口变大会自动重渲染；点一下预览图放大到屏幕像素 1:1（可滚动查看细节），再点或按 Esc 回到适应窗口。左右两栏可以用标题栏的 ◧ ◨ 按钮或键盘 `[` `]` 收起，让预览占满窗口，设置会被记住。左侧文件列表有「小图／大图」两档缩略图。
- 监看：RGB 直方图（标出高光溢出和暗部死黑的比例），以及亮度波形图／RGB 分量波形图。
- 「按住对比原图」可以看调整前的样子。
- **自动调整**：工具栏的下拉菜单里选测光方案，再点「自动」。之后仍可手动微调。都是按各家相机的测光思路和成片观感做的经验设定，**不是机内算法的复刻**。测光直接在编辑器的真实渲染结果上做，RAW 的起始提亮、JPEG 的直出亮度、当前色温色调和已选的镜头暗角都算在里面。

  每个方案先定**曝光**，再定**整体影调**（设置「对比度／黑色／白色」三个滑块）：

  | 方案 | 测光 | 影调 |
  |---|---|---|
  | 全局评价 | 整幅画面分 6×4 区，去掉最亮、最暗的 15% 分区再平均，目标 18% 灰 | 中性：黑位、白位适中，对比不加不减 |
  | 徕卡经典中央重点（默认） | M 机身式中央重点，目标比 18% 灰低约 1/4 档；暗景只补一部分 | 深沉：黑位压得最深、基础对比 +12，从不降低对比 |
  | 徕卡全局测光 +0.3EV | 徕卡多区测光，再加 +0.3 档补偿 | 同徕卡，略通透（基础对比 +8） |
  | 富士中央重点 | 中央区域比徕卡更宽，目标 18% 灰；高光保护更严 | 柔和：黑位留一点、基础对比 −5、过渡平缓 |

  影调的规则：平淡发灰的画面多加一点对比，已经很硬的少加或略减；对比只看去掉纯黑纯白之后“有内容”的部分，所以大面积黑底的低调照片不会被误判。黑色只往深压（纯黑不会被抬成灰黑），白色只往亮推（到顶的纯白不会被压成灰白）；低调照片不硬拉白，高调照片不硬压黑。所有方案在高光溢出过多时都会收一点曝光。上次选的方案会被记住。

  HDR 动态测光暂时不提供，之后会和 HDR 显示模式一起推出。
- **镜头暗角**：在「基本调整」下方选镜头和强度，模拟经典徕卡 M 镜头未经机身校正的光学暗角（正圆、渐变、四角最暗）：

  | 型号 | 镜头 | 弱（≈f/5.6） | 中（≈f/2.8） | 强（光圈全开） |
  |---|---|---|---|---|
  | 11874 | Summilux-M 35mm f/1.4 ASPH.（1994 版，非 FLE） | −0.6 档 | −1.2 档 | −2.2 档（f/1.4） |
  | 11699 | APO-Summicron-M 35mm f/2 ASPH. | −0.8 档 | −1.3 档 | −1.9 档（f/2） |
  | 11141 | APO-Summicron-M 50mm f/2 ASPH. | −0.5 档 | −0.9 档 | −1.4 档（f/2） |
  | 11672 | Summicron-M 28mm f/2 ASPH.（2016 第二代） | −1.0 档 | −1.6 档 | −2.3 档（f/2） |

  数值是四角比中心暗多少档。徕卡的数据表只以曲线图给出暗角，没有公开数值，这里是按各镜头的设计特点（焦距、最大光圈、镜身大小）做的近似；大光圈、广角的暗角从更靠近中心的地方开始。M 机身拍摄时通常会按镜头编码自动校正暗角，这里模拟的是校正前的光学原貌。导出时同样生效；「基本调整」的「重置」会一并清除。
- 调整会自动保存到 `照片文件夹/photo-cull-report/edits/`，原文件不会被修改。「复制设置／粘贴设置」可以把一张的调整用到另一张。

**支持的格式**
- RAW 由 LibRaw（rawpy）解码：徕卡 DNG（M11、Q3、SL 等）、松下 DNG／RW2、索尼全部 ARW（未压缩、压缩、无损压缩）、富士 RAF（X-Trans 和拜耳机型，包括压缩 RAF）。DNG 里的 BaselineExposure 会自动套用。
- 也能编辑 JPG、HEIC、TIFF、PNG。
- 如果 RAW 解码失败（比如非常新的机型 LibRaw 还不支持），会自动改用 RAW 里嵌入的预览图编辑，并在界面上提示；这时画质和宽容度有限。

**风格（LUT）**
- **内置 LUT**：工具文件夹的 `luts/` 里自带 39 个 LUT：Fujifilm GFX 胶片模拟 20 个（命名「机型 + 胶片模拟名 (sRGB)」，如 `GFX50S PROVIA (sRGB)`）、Leica Look 19 个（命名「Leica Look + 滤镜名 (sRGB)」，如 `Leica Look CHR (sRGB)`）。**工作空间均为 sRGB**，用在已转成 sRGB 的画面上，不要套在 Log 或线性素材上。LUT 收集自公开渠道，品牌名只用于说明风格。默认就用它们，拷到别的电脑（包括 Windows）也能直接用；编辑记录里保存的是「内置 LUT 的名字」而不是这台电脑上的路径。
- **添加自己的 LUT**：在「风格（LUT）」里点「添加 LUT…」选一个或多个 `.cube` 文件，会先检查格式再存到 `~/.photo-cull/luts`（升级工具不会丢），列表里显示在「我的 LUT」分组；鼠标移到条目上点 × 可移除。
- 搜索后点一下 LUT 就能套用，强度可以调。想用别的素材库，点「选择…」换文件夹；点「内置」换回来。选择外部素材库时，列出里面全部的 LUT 和预设。
- **输入空间**：统一按 sRGB 处理，对应索尼「ST 标准」／徕卡「STD」的机内画面。
  - JPEG：用 ST／STD 模式拍的 JPEG，和 LUT 的设计输入完全对应。
  - RAW：以编辑器的标准渲染作为这一画面的近似，再套 LUT。
- S-Log3 等相机 Log 的转换暂未启用（代码里保留，`editor.py` 中的 `ENABLE_LOG`）。
- 编辑器也能解码 XMP 预设里的 Adobe 色彩表（RGBTable／LookTable）；当前素材库范围内没有 XMP，这部分暂时用不到。

**导出**
- JPEG（可选质量，内嵌 sRGB 色彩配置和拍摄参数）或 16 位 TIFF；可以选原尺寸，或把长边缩到 6000／4000／2048。
- 导出到照片所在文件夹的 `photo-cull-export` 子文件夹，不会覆盖原图。
- 导出时按全分辨率解码、分条渲染，6000 万像素的照片也不会占满内存。预览和导出用的是同一条处理管线，每条内部再多线程处理。

**说明**
- 高光、阴影是全局曲线调整，不像 Lightroom 那样做局部色调映射，大幅推动时效果会不同。
- 预览在后台渲染：拖动滑块时先出低清图，松手后再出高清图。渲染会用满电脑的多个核心；大 JPEG 预览按需缩小解码，缩略图优先用文件里内嵌的小预览图（索尼 JPEG、ARW 都带），文件夹打开得更快。
