## 1. 项目概述

本地运行的 Python 照片工具，由两个独立程序组成，共用一个本地网页服务（`gui.py`）：

| 程序 | 启动 | 作用 |
|---|---|---|
| 照片筛选 | `gui.py --app cull`（`启动筛选`） | 本地打分、AI 细评、XMP 星级/色标、RAW+JPEG 配对、HTML 报告、整理与重命名输出 |
| 照片编辑 | `gui.py --app edit`（`启动编辑`） | 基础修图：滑块、曲线、直方图/波形、LUT、自动调整、镜头暗角，导出 JPEG / 16 位 TIFF |

只依赖本机：图片不上传（AI 细评除外，需用户自己填 API Key）。界面、报告和 AI 评语支持简体中文、English、日本語。

## 2. 源码结构

```
cull.py          照片筛选核心：读图/EXIF、打分、AI 细评、XMP、整理输出、生成报告、命令行
editor.py        照片编辑核心：解码、渲染管线、LUT、自动调整、暗角、导出、素材库
gui.py           本地网页服务：提供 web/ 页面和 /api 接口、两个程序的注册与互相跳转、语言切换
desktop.py       桌面应用入口（Mac 应用从这里启动）：一体模式起两个服务 + pywebview 原生窗口；--selftest 自检
i18n.py          多语言：读取 locales/、t("键") 取词、当前语言（命令行 > 环境变量 > 界面选择 > 系统语言）
web/             前端（纯 HTML/CSS/JS，无构建步骤）
  common/        tokens.css（设计变量，含深色模式和分语言字体）、i18n.js（T()、applyI18n()、语言菜单）
  cull/          照片筛选界面：index.html、app.css、app.js
  edit/          照片编辑界面：index.html、app.css、app.js
  report/        报告模板：report.html、report.css、report.js（生成时连同语言包内联成单个文件）
  shell/         一体窗口：两个界面各一个 iframe，切换只换显示
  help.html      另一个程序没开时的提示页（一体模式下基本用不到）
locales/         语言包：zh-CN.json（原文）、en.json、ja.json，按分组嵌套（common、cull、report、edit、server、flag、tier、genre）
luts/            内置 LUT（39 个 .cube，sRGB）和说明
tools/           setup_env.py（部署环境）、make_release.py（生成测试包）、check_i18n.py（检查语言包）、build_mac_app.py（打包 Mac 应用）
packaging/       photo-cull.spec（PyInstaller 配置）、icon.icns／icon.png（应用图标）
windows/         Windows 启动脚本（PowerShell）
docs/            工作记录、测试计划、GUI 设计方向
安装环境 / 启动筛选 / 启动编辑   macOS 用 .command，Windows 用 .bat（文件名不随语言变化）
```

## 3. 功能与实现要点

### 3.1 照片筛选（`cull.py`）
- **配对**：同文件夹、同名（不区分大小写）的 RAW 和 JPEG 视为一组，共用一个 XMP 边车文件。
- **写入**：星级与色标写 XMP；JPEG 可另写内嵌 XMP，写完逐字节核对图像数据未变。
- **删除**：走系统废纸篓（send2trash），失败时移到 `_待删除` 文件夹，不直接删。
- **整理输出**：`保留/淘汰` × `JPEG/RAW` 两层目录，可选复制或移动；清单文件 `.photo-cull-organize.json` 让重复运行不产生重复文件；重名加 `-2`（一组文件共用同一后缀）；RAW 的 XMP 跟着 RAW 走。在报告里改星级或删除后，输出文件夹同步更新。
- **重命名**：`星级_机型_原名`（如 `4_ILCE-1M2_DSC01234.ARW`，淘汰为 `X_`），机型来自 EXIF 并去掉非法字符，只改输出文件夹里的文件。
- **富士 RAF**：识别文件头 `FUJIFILMCCD-RAW`，按偏移 84/88 读取内嵌 JPEG。
- **命令行**：`--organize [DIR] --by-result --by-format --rename --move`、`--lang zh-CN|en|ja`、`--provider … --base-url …`。
- **保存的数据不含语言**：问题标记存代码（`blur`、`soft`、`under`、`over`、`clip_high:0.052`、`clip_low:…`、`eyes`、`xmp_fail:原因`），题材存 `portrait/street/landscape/architecture/event/other`，显示时再翻译；载入 1.5 及以前的结果时把中文句子转换成代码（`FLAG_LEGACY`、`GENRE_LEGACY`）。
- **整理文件夹名**：保留／淘汰 两个文件夹的名字按整理时的语言取（`保留/淘汰`、`Keep/Rejected`、`採用/不採用`），记在整理记录的 `keep_dir`／`reject_dir` 里，之后改星级同步时沿用；没有记录的旧整理按中文名处理。

### 3.1.1 AI 细评
- `PROVIDERS`：每家的显示名、环境变量、默认模型、可选模型和说明（`notes` → 语言包 `cull.model_note.*`）、调用方式 `api`：
  - `messages`：Claude（anthropic SDK）；`responses`：ChatGPT、Grok（openai SDK 的 Responses API）；`gemini`：Gemini REST；
  - `chat`：OpenAI 兼容 Chat Completions，用标准库直接发 HTTP（`_chat_caller`），DeepSeek 和自定义接口走这里，不需要 SDK。
- 模型列表（2026-10 核对，只列能看图的）：Claude sonnet-5-5／haiku-5-5／opus-5-5／fable-5-1；ChatGPT gpt-6.1-sol（默认）／gpt-6-luna／gpt-6-astra／gpt-5.5；Grok grok-4.7；Gemini 3.8-flash／3.6-flash／3.5-flash-lite／4-argon；DeepSeek deepseek-flash（DeepSeek 唯一支持图片输入的模型，v4-pro 只支持文字）。
- 自定义接口：用户填 `base_url` 和模型名（`--provider custom --base-url …`），Key 用界面填写或 `PHOTO_CULL_CUSTOM_API_KEY`；本地服务没有 Key 时自动用占位值。
- 提示词 `AI_PROMPTS` 按语言各一份，要求评语和改进点用该语言写；缓存键为 `服务商:模型:语言:图片哈希`，1.5 及以前的中文缓存在中文界面下仍可命中。

### 3.2 照片编辑（`editor.py`、`web/edit/`）
- **渲染管线**：线性 ProPhoto → 白平衡/曝光 → 镜头暗角 → LookTable → 基础色调（仅 RAW）→ sRGB 编码 → 曲线/RGBTable → 清晰度 → 饱和度、自然饱和度、用户曲线、LUT、黑白。预览和导出走同一条管线。
- **自动调整**（`METER_STYLES`）：全局评价、徕卡经典中央重点（默认）、徕卡全局 +0.3EV、富士中央重点。曝光在真实渲染结果上二分求解（中央重点用高斯加权，全局用 6×4 分区去极值），阻尼防止过度调整，高光过曝保护；之后按方案设定对比度、黑场、白场。HDR 动态方案在 `HDR_STYLES` 里，由 `ENABLE_HDR=False` 隐藏。
- **镜头暗角**（`LENSES`）：11874（35/1.4）、11699（35/2 APO）、11141（50/2 APO）、11672（28/2）× 弱/中/强（约等于 f/5.6、f/2.8、全开）。模型为线性空间里的 `ev · r^p`；数值是根据公开曲线估计的近似值。
- **LUT**：
  - 内置 39 个，见第 4 节。引用写成 `builtin:相对路径`。
  - 用户添加的 LUT 存在 `~/.photo-cull/luts`，引用写成 `user:文件名`，在列表里归入「我的 LUT」。添加时检查格式（必须有 LUT_3D_SIZE 2–129 或 LUT_1D_SIZE，数据完整，单个文件不超过 64 MB），重名自动加 `(2)`；只能移除自己添加的文件。接口：`/api/edit/lut_add`、`/api/edit/lut_remove`。
  - 也可以把素材库切到任意外部文件夹（列出其中全部 `.cube` 和 `.xmp` 预设）。
- **界面**：缩略图小图/大图切换，左右面板可折叠（`[` `]`），点击放大，预览分辨率按显示尺寸在 1400/1800/2400/2880 中选择。

### 3.3 前后端分离与多语言
- `gui.py` 收到 `/` 时读取 `web/<app>/index.html`，替换 `__VER__`、`__LANG__`、`__I18N__`（当前语言的语言包 JSON）后返回；`/static/*` 提供 `web/` 下的 CSS/JS（只允许这些扩展名，不需要令牌）。每次请求都读文件，改界面刷新即可。
- 语言包：`i18n.strings(lang)` = 简体中文 ← 英文 ← 所选语言 逐层覆盖，缺的条目自动回退；网页端缺键会在控制台警告。`common.file_manager`／`common.trash` 由 `gui.py` 按系统（访达／资源管理器、废纸篓／回收站）补上。
- 语言选择：右上角下拉 → `POST /api/lang` 写 `~/.photo-cull/lang.json`（两个程序共用）→ 刷新；筛选程序已有结果时按新语言重新生成报告。第一次打开（没有保存过）按浏览器语言自动选择。
- 后端显示用的名字（测光方案、镜头、暗角档位、LUT 分组、不支持的预设项）都在取用时翻译（`meter_list()`、`lens_list()`、`vig_levels()`、`builtin_group_label()`、`unsup_text()`）；LUT 文件夹名本身不变，免得编辑记录里的引用失效。
- 报告页：`write_report()` 把 `tokens.css`、`report.css`、`i18n.js`、`report.js`、报告用到的语言分组和数据内联进一个 `report.html`，可以单独拷走打开。CSV 表头也按语言写。
- 检查工具：`tools/check_i18n.py` 检查三种语言键是否一致、占位符是否一致、代码里直接引用的键是否都存在。

### 3.4 两个程序的协作（`gui.py`）
- **一体模式（默认）**：`gui.py --app all --start cull|edit`（启动文件、Mac 应用都用它）在同一进程里起两个本地服务（各一个端口，`server.app` 区分），`/shell` 页面用两个 iframe 装两个界面；页头切换按钮、⌘1／⌘2、报告里的「编辑」通过 `postMessage` 通知外层切换（`web/common/shell.js`）。当前界面和编辑中的照片记在地址参数里，整页刷新（切换语言）后回到原处；筛选页刷新后从 `/api/status` 恢复进度或结果。再次启动时发现已有一体进程，直接打开它的窗口。
- **单独模式**：`--app cull|edit`，需要另一个程序时自动在后台启动（`start_peer`，打包后的应用不需要）；设置 `PHOTO_CULL_NO_AUTOSTART=1` 可关闭（测试用）。
- **Mac 应用**：`tools/build_mac_app.py` 在单独的 `.venv-build` 里装 PyInstaller、pywebview，按 `packaging/photo-cull.spec` 打包成 `dist/mac/照片工具.app`（web、locales、luts 作为资源打进去），再运行 `PhotoCull --selftest` 自检，最后用 `ditto` 生成分发用 zip。窗口用 pywebview（系统 WebKit），不能开新标签页的地方（「在浏览器中打开报告」）改由后端调用默认浏览器。应用日志在 `~/.photo-cull/logs/app.log`，网页存储在 `~/.photo-cull/webview`。
- 每个程序启动后写注册文件 `~/.photo-cull/apps/<app>.json`（端口、令牌、进程号，权限 600）。
- `/open/<app>` 跳转到另一个程序；对方没开时显示启动提示页。
- 跨程序接口互相隔离（筛选端访问编辑接口返回 404，反之亦然）。

### 3.5 性能
- JPEG/MPO 按需缩小解码（PIL draft）；缩略图优先用文件内嵌的小预览（索尼 JPEG、ARW 都带）。
- 渲染缓存、按预览级别缓存缩放图；平面（R/G/B 分开）内存布局；四面体插值 3D LUT 重写（结果与旧实现逐位一致）；逐像素阶段多线程分块，清晰度等整图阶段单独处理。
- 实测（2 核容器，2880 档）：LUT 渲染 1737 → 649 ms，拖动预览约 36 ms。

### 3.6 部署与打包
- `tools/setup_env.py`：找 Python ≥ 3.9 → 建独立环境（macOS/Linux `.venv`，Windows `.venv-win`）→ PyPI 4 秒连不上就换清华镜像 → 安装依赖 → 逐个导入检查组件、核对 LUT 数量和设置文件夹可写。用 `requirements.txt` 的哈希判断环境是否需要更新。参数：`--check --recreate --mirror tuna|aliyun|ustc|pypi --wheels DIR --download DIR --target win|mac-arm|mac-intel|linux`。
- Windows：`.bat` → `windows/run.ps1` / `setup.ps1`（UTF-8 BOM、CRLF），缺 Python 时用 winget 装 3.12。ARM 版 Windows 不支持（RAW 解码库无 ARM 版）。
- `tools/make_release.py` 生成 `dist/照片工具-<版本>-Windows.zip` / `-macOS.zip`（各约 16.6 MB）。

## 4. 内置 LUT

| 分组 | 数量 | 命名规则 | 示例 |
|---|---|---|---|
| `Fujifilm GFX 胶片模拟 (sRGB)` | 20 | 机型 + 胶片模拟名 (sRGB) | `GFX50S PROVIA (sRGB)`、`GFX100 II REALA ACE (sRGB)` |
| `Leica Look (sRGB)` | 19 | Leica Look + 滤镜名 (sRGB) | `Leica Look CHR (sRGB)`、`Leica Look BW HC (sRGB)` |

- 工作空间全部为 sRGB：文件名、`TITLE` 和文件头注释都有标注，编辑器按 sRGB 套用。
- LUT 收集自公开渠道；文件头里原有的宣传注释已去掉，调色数据未改动（与原文件逐个核对一致）。
- 改名过程：原始文件名 → 一度改为中性名（C01–C23 / M01–M16）→ 现名。三代名字到现名的对照在 `lut-aliases.json`（工具文件夹或 `~/.photo-cull` 里，已列入 `.gitignore`，不发布），旧编辑记录据此自动对应。

## 5. 主要问题与修复

| 问题 | 原因 / 修复 |
|---|---|
| 缩略图卡片被压扁 | 自动高度网格里 `overflow:hidden` → 改用内边距包裹层 + `grid-auto-rows:max-content` |
| 折叠左面板后布局错列 | 给各区域固定 `grid-column` |
| 分块导出与整图渲染有细微差别 | 暗角坐标改 float64；清晰度分块边距改 4σ+2 |
| 奇数尺寸图片尺寸差 1 像素 | 保存原始尺寸，按旋转方向还原 |
| 索尼 JPEG（MPO）没走快速解码 | 补充 MPO 格式和预览帧逻辑 |
| 最终着色阶段慢 | 改为索引查表 + 平面缓冲 |
| 清晰度+饱和度并行后反而变慢 | 拆分逐像素阶段（并行）和整图阶段 |
| 设备同步偶尔写入旧内容 | 每次部署用新的暂存目录，并核对 md5 |
| 切换语言后筛选页仍是中文 | 图形界面在同一进程里调用 `cull.main --lang`，覆盖值没有还原 → 不再传 `--lang`，且 `cull.main` 结束时恢复原值 |
| 选中文时显示成英文 | 语言回退顺序写反（英文覆盖了中文）→ 改为 简体中文 ← 英文 ← 所选语言 |
| 日文界面「入力色空間」竖排 | 标签写死 62px 宽 → 改为不换行、自适应宽度 |
