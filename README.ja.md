# photo-cull

[简体中文](README.md) · [English](README.en.md) · **日本語**

photo-cull には 2 つのプログラムが**1 つのウィンドウ**に入っていて、右上でいつでも切り替えられます（⌘1／⌘2）。どちらの状態も保たれます。macOS ではターミナル不要の **「照片工具.app」** として単体アプリにできます（下の「Mac アプリ」を参照）。

- **写真セレクト**（macOS は `启动筛选.command`、Windows は `启动筛选.bat` をダブルクリック）：パソコン上で技術的なセレクトを行います。ピント、ブレ、露出、顔と目つぶりの検出、連写や同じシーンの撮り直しのグループ分け。候補に残った写真は **Claude、ChatGPT、Grok、Gemini、DeepSeek**、または OpenAI 互換の任意のビジョンモデル（OpenRouter、Qwen、ローカルの Ollama など）で講評できます。**レーティングとカラーラベル**は XMP に書き込まれ、Lightroom Classic と Capture One の両方で読めます。操作できる Web レポートも作成します。
- **写真編集**（`启动编辑.command`／`启动编辑.bat`、ベーシック版）：画面全体の補正、トーンカーブ、ヒストグラムと波形モニター。`.cube` LUT と Lightroom／Photoshop の XMP プリセットを適用し、JPEG または 16 ビット TIFF で書き出します。Leica DNG、Panasonic DNG、すべての Sony ARW、富士フイルム RAF に対応。

> 起動ファイル名は中国語のままです：`安装环境`＝環境のインストール、`启动筛选`＝写真セレクトを起動、`启动编辑`＝写真編集を起動。

**表示言語**：简体中文、English、日本語。どちらのプログラムでも右上で切り替えられます（両方に反映）。レポート、実行ログ、AI の講評も選んだ言語になります。初回はブラウザーの言語に合わせて自動で選びます。

**RAW＋JPEG のペア**：同じフォルダーにある同名の RAW（DNG、ARW、RAF など）と JPEG は 1 枚の写真として扱います。レーティングは両方に書き込まれ、削除するときも両方まとめて削除します。

**安全性**
- 画像データは決して変更しません。
  - RAW のレーティングは同名のサイドカー `.xmp` に書き込み、RAW ファイル自体には触れません。
  - JPEG のレーティングはファイル内の XMP セグメントに書き込みます（メタデータのみ）。書き込み後、画像データ（カメラが付ける複数画像のプレビューを含む）を 1 バイトずつ照合し、少しでも異常があれば書き込みを取りやめます。
- 既存の XMP はレーティングとラベル以外（現像設定、キーワードなど）をそのまま残します。他のソフトが書いたサイドカーを初めて変更する前に、`.xmp.cull-bak` としてバックアップします。
- 「削除」はファイルを**ゴミ箱**に移すだけなので、元に戻せます。
- 整理は既定で**コピー**です。元のフォルダーはそのまま残り、「移動」を選んだときだけファイルを動かします。

## インストール（最初の 1 回だけ）

**macOS**：`安装环境.command` をダブルクリックします（起動ファイルをダブルクリックしても初回は自動でインストールされます。2 つのプログラムは同じ環境を使います）。Python 3.9 以降（[python.org](https://www.python.org/downloads/)）が必要です。

**Windows（ベータ版）**：`安装环境.bat` をダブルクリックし、その後は `启动筛选.bat`／`启动编辑.bat` で開きます。
- 初回は環境を自動で準備します。Python がない場合は Enter を押すと Windows 標準の winget で Python 3.12 を現在のユーザーにインストールし、続いて依存パッケージをダウンロードします（約 3〜5 分）。2 回目以降はすぐに開きます。
- 「Windows によって PC が保護されました」と出たら、「詳細情報 → 実行」を押してください。
- 64 ビット版 Windows 10／11（x64）が必要です。ARM 版 Windows にはまだ対応していません（RAW デコード用ライブラリーに ARM 版がないため）。
- Windows 用の環境は `.venv-win` で、macOS の `.venv` とは別です。同じフォルダーを両方の OS で共有できます。

### 新しいパソコンへの導入

新しいパソコンや、環境が壊れたときは **`安装环境.command`**（macOS）／**`安装环境.bat`**（Windows）をダブルクリックします。次の処理を行います。

1. Python を探します（Windows では winget で自動インストールも可能）。
2. ツールのフォルダー内に専用の環境（macOS は `.venv`、Windows は `.venv-win`）を作ります。パソコン上の他の Python には影響しません。
3. `requirements.txt` の依存パッケージをインストールします。まず PyPI 公式を試し、4 秒以内につながらなければミラーに切り替えます。
4. 各コンポーネントが本当に使えるか 1 つずつ確認し（numpy、Pillow、OpenCV、rawpy／LibRaw、ExifRead は必須。HEIC、ゴミ箱、AI 講評は任意）、内蔵 LUT と設定フォルダーも確認して結果を表示します。

導入後、起動ファイルは短い確認だけしてすぐ開きます。`requirements.txt` が変わったときは自動で追加インストールします。

ターミナルでは次のオプションが使えます（Windows は `安装环境.bat オプション`）。

| オプション | 内容 |
|---|---|
| `--check` | 確認のみ（インストールしない） |
| `--recreate` | 環境を削除して作り直す（壊れたときや Python を変えたとき） |
| `--mirror tuna`／`aliyun`／`ustc`／`pypi`／URL | pip の取得元を指定（既定は `auto`） |
| `--wheels フォルダー` | ローカルのフォルダーからオフラインでインストール |
| `--download フォルダー --target win／mac-arm／mac-intel／linux` | ネットにつながるパソコンで相手の OS 用パッケージを先にダウンロード（`--target-python 3.12` と併用）し、持って行って `--wheels` でオフラインインストール |

macOS で手動インストールする場合は「ターミナル」で：

```bash
cd ~/Desktop/照片筛选工具
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

## Mac アプリ（おすすめ）

ツールのフォルダーにある **`打包Mac应用.command`**（Mac アプリの作成）をダブルクリックすると `dist/mac/照片工具.app` ができます。
- Python とすべての依存パッケージを同梱しているので、他の Mac（Apple シリコン、macOS 11 以降）でもそのまま使えます
- ネイティブのウィンドウで、ターミナルもブラウザーも開きません。写真セレクトと写真編集は同じウィンドウで切り替えます
- 初回はパッケージ作成ツールをダウンロードするため 3〜8 分ほどかかります。専用の `.venv-build` を使い、普段の `.venv` には影響しません
- 作成後に自己診断（依存パッケージ、内蔵 LUT、2 つのサービス）を行い、配布用の `dist/照片工具-<バージョン>-macOS-app.zip` も作ります

`照片工具.app` を「アプリケーション」に入れ、Launchpad や Dock から開いてください。ウィンドウを閉じると終了します。ログは `~/.photo-cull/logs/app.log`、作成時の記録は `dist/mac/build.log` にあります。
他の人が作ったアプリをダウンロードした場合は、初回のみ右クリック →「開く」で起動してください（Apple の公証を受けていないため）。

## 画面での使い方

**`启动筛选.command`** か **`启动编辑.command`** をダブルクリックすると、ブラウザーで同じ「写真ツール」のウィンドウが開き、それぞれ写真セレクトか写真編集から始まります。右上の「写真セレクト｜写真編集」で切り替えられるので、もう一方の起動ファイルを開く必要はありません。すでに起動している場合は、2 つ目を起動せず既存のウィンドウを開きます。

写真セレクトの使い方：

1. 「選択…」で写真フォルダーを選びます。以前にセレクトしたフォルダーなら「このフォルダーの前回の結果を読み込む」で続きから確認できます。
2. 「ローカルのみ」か「ローカル＋AI 講評」を選びます。AI 講評では：
   - サービスを選びます：Claude、ChatGPT、Grok、Gemini、DeepSeek、カスタム
   - 一覧からモデルを選びます（おすすめ／安価／最高性能などの表示つき）。「その他」を選んで手入力もできます
   - そのサービスの API キーを入力します。カスタムの場合はエンドポイントの URL も入力します
3. 初回は「ドライラン」をオンにして、判定の傾向を確認するのがおすすめです。
   「整理して出力」をオンにすると、評価後にフォルダー分けと名前変更を行います（下の「整理して出力」を参照）。
4. 「セレクト開始」を押します。AI を呼び出す前に枚数と使用量の見込みを表示し、確認してから送信します。
5. 終わるとレポートが画面に表示されます。レポートでは：
   - ★ でレーティングを変更、✕ で却下。変更はすぐ RAW と JPEG に書き込まれます
   - 写真のチェックボックスを選んで「選択を削除」、または「不採用をすべて削除」。ペアのファイルと XMP もまとめてゴミ箱へ移動します
   - 確認後「現在のレーティングで整理」を押すと、変更後のレーティングで出力フォルダーに整理します
   - 写真の「編集」で、写真編集に切り替えてその写真を開きます

すべてこのパソコン上（127.0.0.1）で動き、外部からはアクセスできません。終了するにはターミナルウィンドウを閉じます。
macOS で「開発元が未確認のため開けません」と表示された場合：起動ファイルを右クリック →「開く」→ もう一度「開く」。

## AI 講評で使えるモデル

| サービス | モデル（先頭が既定） | API キーの取得先 | 環境変数 |
|---|---|---|---|
| Claude | `claude-sonnet-5-5`（おすすめ）、`claude-haiku-5-5`（安価）、`claude-opus-5-5`（高性能）、`claude-fable-5-1`（最高性能・高価） | console.anthropic.com | `ANTHROPIC_API_KEY` |
| ChatGPT | `gpt-6.1-sol`（おすすめ）、`gpt-6-luna`（安価）、`gpt-6-astra`（最高性能）、`gpt-5.5`（前世代） | platform.openai.com | `OPENAI_API_KEY` |
| Grok | `grok-4.7` | console.x.ai | `XAI_API_KEY` |
| Gemini | `gemini-3.8-flash`（おすすめ）、`gemini-3.6-flash`、`gemini-3.5-flash-lite`（安価）、`gemini-4-argon`（最高性能） | aistudio.google.com | `GEMINI_API_KEY`（または `GOOGLE_API_KEY`） |
| DeepSeek | `deepseek-flash` | platform.deepseek.com | `DEEPSEEK_API_KEY` |
| カスタム | 任意 | 各サービス | `PHOTO_CULL_CUSTOM_API_KEY` |

- 一覧は 2026 年 10 月時点で確認したもので、画像を入力できるモデルだけを載せています。新しいモデルが出たら「その他（手入力）」で名前を入力してください。
- **DeepSeek**：現在、画像を扱えるのは `deepseek-flash` だけです（`deepseek-v4-pro` はテキストのみ）。そのため選択肢は 1 つです。
- **カスタム（OpenAI 互換）**：エンドポイントとモデル名を入力すれば、Chat Completions で画像入力に対応する任意のサービスを使えます。例：
  - OpenRouter `https://openrouter.ai/api/v1`
  - Qwen（国際版）`https://dashscope-intl.aliyuncs.com/compatible-mode/v1`（モデル例 `qwen-vl-max`）
  - ローカルの Ollama `http://127.0.0.1:11434/v1`、LM Studio `http://127.0.0.1:1234/v1`（キー不要）

  URL とモデル名は各サービスのドキュメントで確認してください。DeepSeek とカスタムは HTTP で直接呼び出すため、SDK の追加インストールは不要です。
- API キーは従量課金で、Web 版のサブスクリプション（Claude Pro、ChatGPT Plus など）とは別です。
- 講評済みの写真は再度課金されません。キャッシュは「サービス＋モデル＋言語＋画像」ごとに記録します。表示言語を変えると、講評をその言語にするため 1 回だけ再講評します。
- 最初の 3 回が続けて失敗した場合（キーやモデル名の誤り、残高不足など）、自動で講評を止めます。

## コマンドライン

```bash
# ローカルのセレクトのみ（無料）
.venv/bin/python cull.py "/Volumes/SSD/2026-10-19 スナップ"

# まずドライラン：レポートのみ作成し、レーティングは書き込まない
.venv/bin/python cull.py "写真フォルダー" --dry-run

# Claude で講評
export ANTHROPIC_API_KEY="…"
.venv/bin/python cull.py "写真フォルダー" --ai

# ChatGPT／Grok／Gemini／DeepSeek
.venv/bin/python cull.py "写真フォルダー" --ai --provider openai     # OPENAI_API_KEY
.venv/bin/python cull.py "写真フォルダー" --ai --provider grok       # XAI_API_KEY
.venv/bin/python cull.py "写真フォルダー" --ai --provider gemini     # GEMINI_API_KEY
.venv/bin/python cull.py "写真フォルダー" --ai --provider deepseek   # DEEPSEEK_API_KEY

# 任意の OpenAI 互換エンドポイント（例：OpenRouter）
export PHOTO_CULL_CUSTOM_API_KEY="…"
.venv/bin/python cull.py "写真フォルダー" --ai --provider custom --model <モデル名> --base-url https://openrouter.ai/api/v1

# レポート・ログ・AI 講評を日本語で（zh-CN／en／ja）
.venv/bin/python cull.py "写真フォルダー" --lang ja

# レーティング後、不採用の写真（ペアのファイルを含む）をゴミ箱へ
.venv/bin/python cull.py "写真フォルダー" --trash-rejects

# 整理：採用／不採用 × JPEG／RAW の 2 階層、名前変更つき（既定はコピー。--move で移動）
.venv/bin/python cull.py "写真フォルダー" --organize "出力フォルダー" --by-result --by-format --rename
```

レポートは `写真フォルダー/photo-cull-report/report.html` に作られ、同じ場所に Numbers や Excel で開ける `results.csv` もあります。ファイルを直接開いたレポートは閲覧のみです。レーティング変更や削除はプログラムの画面で行ってください。

## 結果とソフトでの見え方

| 結果 | レーティング | ラベル | 意味 |
|---|---|---|---|
| セレクト | 4〜5★ | 緑 | AI 講評でのみ付与。講評なしでは出ません |
| 使える | 3★ | 黄 | 候補だが突出はしていない |
| 連写の控え | 最大 2★ | なし | 同じ連写・撮り直しの中で一番ではない |
| 不採用 | 却下（Rating −1） | 赤 | ひどいピンボケ、露出オーバー／不足。AI が 1★ を付けた場合も赤 |

**書き込み先**

| ファイル | レーティングの書き込み先 |
|---|---|
| RAW（DNG／ARW…） | 同名の `.xmp` サイドカー。RAW＋JPEG のペアで共有 |
| JPEG | ファイル内の XMP（「JPEG 内にも XMP を書き込む」をオフ、または `--no-jpeg-embed` で無効） |
| 単独の HEIC／HIF／PNG | 既定では書き込みません。「単独の JPEG／HEIC にもサイドカー XMP を書き込む」をオンにするとサイドカーを作成（Capture One が読みます） |

**Lightroom Classic**
- 新しく読み込む写真：読み込み時にレーティングを読み取ります。
- すでにカタログにある写真：
  1. 写真を選んで ⌘S（メタデータをファイルに保存）を押し、カタログの最新の変更をファイルに書き出す
  2. photo-cull を実行する
  3. 再び写真を選び「メタデータ → ファイルからメタデータを読み込み」を実行する
- RAW＋JPEG を 1 枚として読み込んだ場合（Lightroom の既定）、Lightroom は RAW のレーティングだけを表示します。両方を見たい場合は、読み込む前に「環境設定 → 一般」で「RAW ファイルと同じ場所にある JPEG ファイルを別の写真として扱う」をオンにしてください。

**Capture One**
- 「環境設定 → イメージ → メタデータ」で XMP サイドカーの自動同期を「完全同期」または「読み込み」にします。その後フォルダーを開くか、画像に「XMP からメタデータを再読み込み」を実行するとレーティングとラベルが表示されます（メニュー名はバージョンにより異なります）。

**削除とカタログ**
- Lightroom や Capture One に読み込み済みの写真をここで削除すると、ソフト側では「ファイルが見つかりません」と表示されます。ソフト側でも削除してください。
- 間違えて削除したら、ゴミ箱を開いてファイルを元のフォルダーに戻せます。

## 整理して出力

レーティング後、写真を出力フォルダーに整理できます（空欄なら `写真フォルダー/整理済み`）。3 つのオプションは個別にオン／オフできます。

- **採用／不採用に分ける**：却下（X）の写真は「不採用」、それ以外は「採用」に入ります。フォルダー名は整理したときの表示言語に従います（中文は `保留`／`淘汰`、English は `Keep`／`Rejected`、日本語は `採用`／`不採用`）。あとでレポートから同期するときも同じ名前を使います。
- **さらに JPEG／RAW に分ける**：HEIC／PNG なども JPEG 側に入ります。
- **名前を変更**：元のファイル名の前に「レーティング_機種_」を付けます。機種は EXIF から取得します。例：
  `4_ILCE-1M2_DSC01234.ARW`、`3_LEICA-M11-D_L1003467.DNG`、`X_X-T5_DSCF0001.RAF`
  却下は `X_`、未評価は `0_`。機種名の空白や記号は `-` に置き換えます。
  **変更するのは出力フォルダー内のファイルだけ**で、元のファイル名は変わりません。

2 階層ともオンにした場合：

```
整理済み/
├── 採用/
│   ├── JPEG/  4_ILCE-1M2_DSC01234.JPG
│   └── RAW/   4_ILCE-1M2_DSC01234.ARW  4_ILCE-1M2_DSC01234.xmp
└── 不採用/
    ├── JPEG/
    └── RAW/
```

**コピーか移動か**
- **コピー**（既定）：元のフォルダーはそのままで、出力にはコピーが入ります（容量は 2 倍必要）。その後レポートでレーティングを変えると、コピーも対応するフォルダーと名前に移ります。写真を削除するとコピーもゴミ箱へ移動します。再度整理しても二重にコピーしません。
- **移動**：写真を元のフォルダーから出力フォルダーへ移します。以後レポートでのレーティング変更や削除は移動先のファイルに反映されます。Lightroom／Capture One に読み込み済みの写真は「ファイルが見つかりません」となるので、ソフト側でフォルダーを再リンクしてください。

**その他**
- ペアの RAW と JPEG は一緒に処理します。RAW のサイドカー `.xmp` も一緒に移動・名前変更するので、出力フォルダーを Lightroom／Capture One に読み込んでもレーティングが見えます。
- 名前が重なると `-2`、`-3` を付けます。ペアの 2 ファイルには同じ番号を付けます。
- ドライランでは計画を表示するだけで、コピーや移動はしません。
- 読み込みに失敗した写真と削除済みの写真は整理しません。
- 出力フォルダーを写真フォルダーの中に置いても構いません。「サブフォルダーも含める」がオンでも、次回のセレクトでは自動で除外します。

## 補足と制限

- **どのファイルを分析するか**：ペアの JPEG があれば JPEG（フルサイズ、カメラ内の色）、なければ RAW の内蔵プレビューを使います。DNG・ARW など TIFF 形式の RAW と富士フイルム RAF は直接読み取り、CR3 などは rawpy が必要です。
- **ペアの条件**：同じフォルダーで、拡張子以外の名前が同じ（大文字小文字は区別しない）。例：`L1003467.DNG` と `L1003467.JPG`。別のフォルダーにあるものはペアになりません。
- **ピント判定**：画像をもう一度ぼかしてエッジの変化量を測る「再ぼかし」指標を使うため、被写体の細かさに左右されません。最もシャープな部分だけを見るので、背景をぼかしたポートレートを誤判定しません。既定のしきい値は Leica M11-D の写真で調整したもので、他の機種では微調整が必要な場合があります。
- **顔と目つぶりの検出**：OpenCV の従来型検出器です。速いものの大まかなので、ヒントとして表示するだけで不採用の理由にはしません。
- **AI 講評**：
  - 候補の写真だけを長辺 1024 ピクセルの JPEG に縮小して送ります
  - 結果は `ai_cache.json` にキャッシュします
  - モデルによって好みが違うため、点数は参考と考え、最終判断はご自身で行ってください

## 写真編集（ベーシック版）

`启动编辑.command` をダブルクリックして開きます。セレクトレポートの写真カード右上の「編集」から、その写真を直接開くこともできます。左上の「セレクト結果」は、写真セレクトで最後に処理したフォルダーを開きます。

**補正**
- 基本：色温度、色かぶり補正、露光量、コントラスト、ハイライト、シャドウ、白レベル、黒レベル、明瞭度、自然な彩度、彩度、モノクロ。スライダー名をダブルクリックするとリセットします。
- トーンカーブ：RGB と赤／緑／青の個別カーブ。クリックで点を追加、ドラッグで調整、ダブルクリックで削除。
- **プレビュー**：画面上で実際に使うピクセル数（Retina を含む）に合わせて解像度を決め、ウィンドウを大きくすると再レンダリングします。プレビューをクリックすると等倍（スクロール可）、もう一度クリックか Esc でウィンドウに合わせます。左右のパネルはタイトルバーの ◧ ◨ かキーボードの `[` `]` で隠せます（設定は記憶されます）。左のファイル一覧はサムネイルの大小を切り替えられます。
- スコープ：RGB ヒストグラム（白飛び・黒つぶれの割合つき）と、輝度波形または RGB パレード。
- 「押して元画像と比較」で補正前の状態を確認できます。
- **自動調整**：ツールバーのメニューで測光方式を選び「自動」を押します。その後も手動で微調整できます。各メーカーの測光の考え方と仕上がりをもとにした経験的な設定で、**カメラ内アルゴリズムの再現ではありません**。測光はエディターの実際のレンダリング結果で行うため、RAW の基準露出、JPEG の明るさ、現在のホワイトバランス、選んだレンズの周辺減光もすべて反映されます。

  各方式はまず**露出**を決め、次に**全体のトーン**（コントラスト／黒レベル／白レベル）を設定します。

  | 方式 | 測光 | トーン |
  |---|---|---|
  | 評価測光（画面全体） | 画面を 6×4 に分割し、最も明るい・暗い 15% を除いて平均、18% グレーが目標 | 中立：黒・白レベルは控えめ、コントラストは増減なし |
  | ライカ伝統の中央重点（既定） | M 型ボディ風の中央重点、18% グレーより約 1/4 段低め。暗いシーンは一部だけ持ち上げ | 深み：黒を最も深く、基準コントラスト +12、コントラストは下げない |
  | ライカ多分割測光 +0.3EV | ライカの多分割測光に +0.3 段の補正 | ライカ調で少し抜けよく（基準コントラスト +8） |
  | 富士フイルム中央重点 | ライカより広い中央部、18% グレー。ハイライト保護は厳しめ | 柔らか：黒は少し残し、基準コントラスト −5、なだらかな階調 |

  トーンの考え方：眠い画像はコントラストを少し上げ、すでに硬い画像は控えめにするか少し下げます。コントラストは純黒・純白を除いた「内容のある部分」だけで判断するので、黒背景の多いローキーを誤判定しません。黒レベルは深くする方向だけ（純黒をグレーに浮かせない）、白レベルは明るくする方向だけ（飽和した白をグレーに沈めない）。ローキーで無理に白を出したり、ハイキーで無理に黒を締めたりはしません。どの方式も白飛びが多すぎるときは露出を少し戻します。前回選んだ方式を記憶します。

  HDR ダイナミック測光はまだ提供していません。HDR 表示モードと合わせて追加する予定です。
- **レンズの周辺減光**：「基本補正」の下でレンズと強さを選ぶと、ボディ補正前のクラシックなライカ M レンズの光学的な周辺減光（正円、なだらか、四隅が最も暗い）を再現します。

  | 型番 | レンズ | 弱（≈f/5.6） | 中（≈f/2.8） | 強（開放） |
  |---|---|---|---|---|
  | 11874 | Summilux-M 35mm f/1.4 ASPH.（1994 年版、FLE 以前） | −0.6 段 | −1.2 段 | −2.2 段（f/1.4） |
  | 11699 | APO-Summicron-M 35mm f/2 ASPH. | −0.8 段 | −1.3 段 | −1.9 段（f/2） |
  | 11141 | APO-Summicron-M 50mm f/2 ASPH. | −0.5 段 | −0.9 段 | −1.4 段（f/2） |
  | 11672 | Summicron-M 28mm f/2 ASPH.（2016 年 第 2 世代） | −1.0 段 | −1.6 段 | −2.3 段（f/2） |

  数値は四隅が中央より何段暗いかです。ライカは周辺減光をグラフでしか公開していないため、各レンズの設計（焦点距離、開放値、大きさ）から推定した近似値です。広角・大口径ほど中央寄りから暗くなり始めます。M 型ボディはレンズコードで周辺減光を自動補正するのが普通ですが、ここでは補正前の光学的な姿を再現します。書き出しにも反映され、「基本補正」の「リセット」で一緒に解除されます。
- 補正は `写真フォルダー/photo-cull-report/edits/` に自動保存され、元のファイルは変更しません。「設定をコピー／設定を貼り付け」で別の写真に同じ補正を使えます。

**対応形式**
- RAW は LibRaw（rawpy）でデコードします：Leica DNG（M11、Q3、SL など）、Panasonic DNG／RW2、すべての Sony ARW（非圧縮、圧縮、ロスレス圧縮）、富士フイルム RAF（X-Trans とベイヤー、圧縮 RAF を含む）。DNG の BaselineExposure も反映します。
- JPG、HEIC、TIFF、PNG も編集できます。
- RAW のデコードに失敗した場合（LibRaw が未対応の新機種など）は、RAW の内蔵プレビューに切り替えて画面に表示します。この場合、画質とラチチュードは限られます。

**スタイル（LUT）**
- **内蔵 LUT**：`luts/` に 39 個の LUT が入っています。富士フイルム GFX フィルムシミュレーション 20 個（名前は「機種＋フィルムシミュレーション名 (sRGB)」、例 `GFX50S PROVIA (sRGB)`）と Leica Look 19 個（名前は「Leica Look＋フィルター名 (sRGB)」、例 `Leica Look CHR (sRGB)`）。**作業色空間はすべて sRGB** です。sRGB に変換済みの画像に使い、Log やリニアの素材には使わないでください。公開されている入手先から集めたもので、ブランド名はスタイルの説明として使っています。編集記録にはこのパソコン上のパスではなく内蔵 LUT の名前を保存するので、別のパソコン（Windows を含む）にコピーしてもそのまま使えます。
- **自分の LUT を追加**：「スタイル（LUT）」の「LUT を追加…」で `.cube` ファイルを 1 つ以上選びます。形式を確認してから `~/.photo-cull/luts` に保存し（アップデートしても消えません）、「マイ LUT」に表示します。項目にマウスを乗せて × で削除できます。
- 検索して LUT をクリックすると適用され、適用量も調整できます。別のライブラリーを使うときは「選択…」でフォルダーを選び、「内蔵」で戻ります。外部ライブラリーでは中のすべての LUT とプリセットを表示します。
- **入力色空間**：常に sRGB として扱い、ソニー「ST」／ライカ「STD」のカメラ内の画づくりに対応します。
  - JPEG：ST／STD で撮影した JPEG は、LUT の想定入力とそのまま一致します。
  - RAW：エディターの標準現像をその画づくりの近似として、LUT を適用します。
- S-Log3 などカメラの Log 変換は現在無効です（コードには残してあり、`editor.py` の `ENABLE_LOG`）。
- XMP プリセット内の Adobe カラーテーブル（RGBTable／LookTable）もデコードできます。

**書き出し**
- JPEG（画質を選べます。sRGB プロファイルと撮影情報を埋め込み）または 16 ビット TIFF。元のサイズのほか、長辺 6000／4000／2048 に縮小できます。
- 写真と同じフォルダー内の `photo-cull-export` に書き出し、元画像は上書きしません。
- 書き出しはフル解像度でデコードし、帯状に分けてレンダリングするので、6000 万画素の写真でもメモリーを使い切りません。プレビューと書き出しは同じ処理パイプラインを使い、各帯は複数スレッドで処理します。

**補足**
- ハイライトとシャドウは全体に効くカーブで、Lightroom のような局所的なトーンマッピングではないため、大きく動かすと結果が異なります。
- プレビューはバックグラウンドでレンダリングします。スライダーを動かしている間は低解像度、離すと高画質になります。CPU のすべてのコアを使い、大きな JPEG は縮小してデコードし、サムネイルはファイル内蔵の小さなプレビュー（ソニーの JPEG と ARW の両方にあります）を優先するので、フォルダーをすばやく開けます。
